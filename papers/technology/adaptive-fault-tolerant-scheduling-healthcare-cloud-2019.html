ចំណងជើងដើម៖ ADAPTIVE AND FAULT-TOLERANT SCHEDULING FOR EFFECTIVE DATA STORING IN HEALTHCARE COMMUNITY USING CLOUD COMPUTING

អ្នកនិពន្ធ៖ Aliyu Muhammad (Universiti Putra Malaysia)

ឆ្នាំបោះពុម្ព៖ 2019 Universiti Putra Malaysia

វិស័យសិក្សា៖ Computer Science

១. សេចក្តីសង្ខេបប្រតិបត្តិ (Executive Summary)

បញ្ហា (The Problem)៖ មជ្ឈមណ្ឌលទិន្នន័យក្លោដតែមួយមានកម្រិតធនធានរូបវន្តក្នុងការរក្សាទុកទិន្នន័យថែទាំសុខភាព ហើយការប្រើប្រាស់សម្ព័ន្ធក្លោដ (Cloud Confederation) ជួបបញ្ហាប្រឈមក្នុងការជ្រើសរើសមជ្ឈមណ្ឌលទិន្នន័យ (CDC) ល្អបំផុត និងខ្វះសមត្ថភាពទប់ទល់នឹងកំហុស (Fault Tolerance) នៅពេលម៉ាស៊ីនមានបញ្ហា។

វិធីសាស្ត្រ (The Methodology)៖ ការស្រាវជ្រាវនេះបានបង្កើតម៉ូដែលកាលវិភាគដែលអាចសម្របតាម និងធន់នឹងកំហុស (FT-FNF) សម្រាប់បរិស្ថានពហុក្លោដ ដោយប្រើប្រាស់បច្ចេកទេសគណិតវិទ្យាដើម្បីវាយតម្លៃ និងគ្រប់គ្រងធនធាន។

  • ការប្រើប្រាស់តក្កវិទ្យាស្រពិចស្រពិល (Fuzzy Logic) សម្រាប់ការសម្រេចចិត្តជ្រើសរើសមជ្ឈមណ្ឌលទិន្នន័យក្លោដដ៏ប្រសើរបំផុត (Optimal CDC)។
  • ការប្រើប្រាស់វិធីសាស្ត្រគុណម៉ាទ្រីសការ៉េ (Square Matrix Multiplication) ដើម្បីព្យាករណ៍ពីស្ថានភាពធនធានកុំព្យូទ័រថាតើមានដំណើរការល្អ ឬមានបញ្ហា (Healthy/Unhealthy Resources)។
  • ការធ្វើត្រាប់តាមប្រព័ន្ធ (Simulation System) ដើម្បីប្រៀបធៀបប្រសិទ្ធភាពម៉ូដែលថ្មី ដោយប្រើប្រាស់កម្មវិធី Cloudsim។

លទ្ធផលសំខាន់ៗ (The Verdict)៖

  • ម៉ូដែល FT-FNF ផ្តល់លទ្ធផលល្អប្រសើរជាងម៉ូដែល FnF ចាស់ ក្នុងការធានាគុណភាពសេវាកម្ម (QoS) សម្រាប់អ្នកប្រើប្រាស់ទិន្នន័យសុខភាព។
  • ប្រព័ន្ធនេះជួយបង្កើនប្រាក់ចំណេញអតិបរមាសម្រាប់អ្នកផ្តល់សេវាក្លោដ និងបង្កើនប្រសិទ្ធភាពនៃការប្រើប្រាស់ធនធាន (Resource Utilization) យ៉ាងពេញលេញ។
  • ការអនុវត្តម៉ូដែលនេះជួយកាត់បន្ថយពេលវេលានៃការប្រតិបត្តិការងារ (Execution Time) កាន់តែឆាប់រហ័សនិងមានលំនឹងក្នុងករណីមានកំហុសប្រព័ន្ធ។

២. ការវិភាគលើប្រសិទ្ធភាព និងដែនកំណត់ (Performance & Constraints)

វិធីសាស្ត្រ (Method) គុណសម្បត្តិ (Pros) គុណវិបត្តិ (Cons) លទ្ធផលគន្លឹះ (Key Result)
FNF (Family and Friends) Model
ម៉ូដែល FNF (Family and Friends)		 បង្កើនប្រាក់ចំណេញ និងការប្រើប្រាស់ធនធានសម្រាប់អ្នកផ្តល់សេវាដោយរក្សាបាននូវគុណភាពសេវាកម្ម (QoS) ក្នុងលក្ខខណ្ឌធម្មតា។ គ្មានសមត្ថភាពទប់ទល់នឹងកំហុស (Fault tolerance) ដែលធ្វើឱ្យមានការរំខានដល់អ្នកប្រើប្រាស់ និងបាត់បង់ប្រាក់ចំណេញនៅពេលប្រព័ន្ធ ឬធនធានមានបញ្ហា។ ចំណាយពេលវេលាប្រតិបត្តិការយូរជាង និងទទួលបានប្រាក់ចំណេញធ្លាក់ចុះនៅពេលមានកំហុសប្រព័ន្ធកើតឡើង។
FT-FNF (Fault-Tolerant FNF) Model
ម៉ូដែល FT-FNF (មានសមត្ថភាពទប់ទល់នឹងកំហុស)		 មានសមត្ថភាពទាយទុកមុនពីធនធានកុំព្យូទ័រដែលខូចខាត (Unhealthy) និងធ្វើការផ្លាស់ទីម៉ាស៊ីននិម្មិត (VM) ដើម្បីធានាប្រតិបត្តិការប្រកបដោយស្ថិរភាព។ ទាមទារការគណនាស្មុគស្មាញ (ដូចជាការគុណម៉ាទ្រីសការ៉េ និងតក្កវិទ្យាស្រពិចស្រពិល) សម្រាប់ការជ្រើសរើសទីតាំង និងការទស្សន៍ទាយធនធាន។ កាត់បន្ថយពេលវេលាប្រតិបត្តិការងារ បង្កើនការប្រើប្រាស់ធនធានអតិបរមា និងធានាបាននូវប្រាក់ចំណេញខ្ពស់សម្រាប់អ្នកផ្តល់សេវា ទោះបីជាមានកំហុសប្រព័ន្ធក៏ដោយ។

ការចំណាយលើធនធាន (Resource Cost)៖ ការអនុវត្តម៉ូដែលនេះតម្រូវឱ្យមានធនធានផ្នែកទន់សម្រាប់ការធ្វើត្រាប់តាម (Simulation) និងកម្រិតចំណេះដឹងផ្នែកកុំព្យូទ័រខ្ពស់។

  • Software: តម្រូវឱ្យប្រើប្រាស់កម្មវិធី CloudSim សម្រាប់ការធ្វើត្រាប់តាមបរិស្ថានក្លោដ និងការសរសេរកូដ។
  • Hardware: កុំព្យូទ័រខ្នាតមធ្យមទៅខ្ពស់ដែលមានអង្គចងចាំ (RAM) គ្រប់គ្រាន់ដើម្បីដំណើរការការធ្វើត្រាប់តាមមជ្ឈមណ្ឌលទិន្នន័យជាច្រើនក្នុងពេលតែមួយ។
  • Dataset: ទិន្នន័យនៃការស្នើសុំប្រើប្រាស់ធនធានក្លោដ (Workload data) និងទិន្នន័យគំរូរូបភាពវេជ្ជសាស្ត្រដូចជា DICOM ជាដើម។
  • Expertise: អ្នកអភិវឌ្ឍន៍ត្រូវមានចំណេះដឹងផ្នែក Cloud Computing, ទ្រឹស្តី Fuzzy Logic, និងការគណនាម៉ាទ្រីស (Matrix Computation)។

៣. ការពិនិត្យសម្រាប់បរិបទកម្ពុជា/អាស៊ីអាគ្នេយ៍

ភាពលំអៀងនៃទិន្នន័យ (Data Bias)៖

ការសិក្សានេះពឹងផ្អែកលើការធ្វើត្រាប់តាម (Simulation) ក្នុងបរិស្ថាន CloudSim ដោយផ្អែកលើការសន្មត់នៃទិន្នន័យវេជ្ជសាស្ត្រ មិនមែនជាការអនុវត្តលើហេដ្ឋារចនាសម្ព័ន្ធពិតប្រាកដឡើយ។ សម្រាប់ប្រទេសកម្ពុជា នេះជាបញ្ហាប្រឈមដោយសារមន្ទីរពេទ្យភាគច្រើនមិនទាន់មានទិន្នន័យ EMR ច្បាស់លាស់ ហើយហេដ្ឋារចនាសម្ព័ន្ធក្លោដក្នុងស្រុកនៅមានកម្រិតនៅឡើយ។

លទ្ធភាពនៃការអនុវត្ត (Applicability)៖

ទោះជាយ៉ាងណាក៏ដោយ វិធីសាស្ត្រនេះមានសក្តានុពលខ្ពស់សម្រាប់ជួយពន្លឿនការផ្លាស់ប្តូរប្រព័ន្ធសុខាភិបាលកម្ពុជាទៅកាន់យុគសម័យឌីជីថលប្រកបដោយសុវត្ថិភាព។

  • ក្រសួងសុខាភិបាល និងមន្ទីរពេទ្យជាតិ (ឧ. មន្ទីរពេទ្យកាល់ម៉ែត): អាចប្រើប្រាស់គំរូនេះដើម្បីរៀបចំប្រព័ន្ធផ្ទុកឯកសារអ្នកជំងឺ (EMR) និងរូបភាពកាំរស្មីអ៊ិច (DICOM) លើក្លោដ ដែលធានាថាមិនបាត់បង់ទិន្នន័យពេលម៉ាស៊ីនសេវើមានបញ្ហា។
  • ក្រុមហ៊ុនផ្តល់សេវាបច្ចេកវិទ្យា និង Cloud (ឧ. Ezecom, Metfone): អាចស្វែងយល់ពីម៉ូដែលសហព័ន្ធក្លោដ (Cloud Confederation) នេះ ដើម្បីផ្តល់សេវាកម្មចែកចាយធនធានប្រកបដោយស្ថិរភាពដល់ស្ថាប័នរដ្ឋនិងឯកជន ជួយសន្សំសំចៃនិងបង្កើនប្រាក់ចំណេញ។
  • ក្រុមហ៊ុន HealthTech Startups នៅកម្ពុជា: អាចយកយន្តការ Fault-Tolerance នេះទៅអនុវត្តក្នុងកម្មវិធីទូរស័ព្ទដៃផ្នែកសុខភាព ដើម្បីធានាថាកម្មវិធីអាចបម្រើសេវាកម្មបាន ២៤ម៉ោង/៧ថ្ងៃ ដោយគ្មានការរអាក់រអួល។

សរុបមក ការរៀបចំប្រព័ន្ធពហុក្លោដដែលធន់នឹងកំហុស គឺជាមូលដ្ឋានគ្រឹះដ៏សំខាន់សម្រាប់គាំទ្រដល់ចក្ខុវិស័យរដ្ឋាភិបាលអេឡិចត្រូនិក និងប្រព័ន្ធសុខាភិបាលឌីជីថលនៅកម្ពុជា។

៤. ផែនការសកម្មភាពសម្រាប់និស្សិត (Actionable Roadmap)

ដើម្បីអនុវត្តតាមការសិក្សានេះ និស្សិតគួរអនុវត្តតាមជំហានខាងក្រោម៖

  1. សិក្សាស្រាវជ្រាវពីបច្ចេកវិទ្យាក្លោដ និងក្បួនដោះស្រាយ: និស្សិតត្រូវចាប់ផ្តើមស្វែងយល់ពីគោលការណ៍កម្រិតខ្ពស់របស់កុំព្យូទ័រក្លោដ និងសាកល្បងសរសេរកូដ Fuzzy Logic ដោយប្រើប្រាស់ MATLAB ឬបណ្ណាល័យរបស់ Python (scikit-fuzzy)។
  2. ដំឡើងបរិស្ថានធ្វើត្រាប់តាម: ទាញយកនិងដំឡើងកម្មវិធី CloudSim រួមជាមួយនឹងកម្មវិធីសរសេរកូដដូចជា Eclipse ឬ IntelliJ IDEA ដើម្បីរៀនពីរបៀបបង្កើតមជ្ឈមណ្ឌលទិន្នន័យនិម្មិត និងកំណត់លក្ខខណ្ឌម៉ាស៊ីន (VMs)។
  3. អភិវឌ្ឍម៉ូដែលវាយតម្លៃហានិភ័យធនធាន: សរសេរកូដបញ្ចូលយន្តការ Square Matrix Multiplication ដើម្បីតាមដានសុខភាពម៉ាស៊ីនសេវើ (Healthy/Unhealthy) និងកំណត់ការផ្លាស់ទីទិន្នន័យស្វ័យប្រវត្តិ។
  4. ធ្វើតេស្តជាមួយទិន្នន័យវេជ្ជសាស្ត្រសិប្បនិម្មិត ឬបើកចំហ: ប្រើប្រាស់សំណុំទិន្នន័យរូបភាពវេជ្ជសាស្ត្រ DICOM ដែលមានស្រាប់ពីវេទិកាដូចជា Kaggle ដើម្បីវាយតម្លៃប្រសិទ្ធភាពម៉ូដែល មុននឹងឈានទៅសហការសាកល្បងជាមួយមន្ទីរពេទ្យពិតប្រាកដក្នុងស្រុក។

៥. វាក្យសព្ទបច្ចេកទេស (Technical Glossary)

ពាក្យបច្ចេកទេស ការពន្យល់ជាខេមរភាសា (Khmer Explanation) និយមន័យសាមញ្ញ (Simple Definition)
Cloud Confederation ការចងសម្ព័ន្ធគ្នារវាងអ្នកផ្តល់សេវាក្លោដ (Cloud Providers) ជាច្រើនកន្លែង ដើម្បីចែករំលែកធនធានគ្នា (ដូចជាម៉ាស៊ីនសេវើ និងកន្លែងផ្ទុក) សំដៅបង្កើនប្រសិទ្ធភាពសេវាកម្ម និងជៀសវាងការខ្វះខាតធនធាននៅពេលមានអតិថិជនប្រើច្រើន។ ដូចជាក្រុមហ៊ុនដឹកជញ្ជូនពីរផ្សេងគ្នាសហការគ្នាដើម្បីដឹកទំនិញឱ្យអតិថិជនបានទាន់ពេល នៅពេលដែលក្រុមហ៊ុនមួយមានឡានមិនគ្រប់គ្រាន់។
Fault Tolerance សមត្ថភាពនៃប្រព័ន្ធកុំព្យូទ័រក្នុងការបន្តប្រតិបត្តិការងាររបស់ខ្លួនជាធម្មតា ទោះបីជាមានផ្នែកណាមួយនៃប្រព័ន្ធ (ដូចជា Hardware ឬ Network) ទទួលរងការខូចខាត ឬគាំងដំណើរការក៏ដោយ។ ដូចជាយន្តហោះដែលមានម៉ាស៊ីនពីរ បើទោះជាម៉ាស៊ីនមួយខូច ក៏យន្តហោះនៅតែអាចហោះហើរ និងចុះចតដោយសុវត្ថិភាពដោយប្រើម៉ាស៊ីនមួយទៀត។
Fuzzy Logic វិធីសាស្ត្រគណិតវិទ្យា និងតក្កវិទ្យាដែលអនុញ្ញាតឱ្យកុំព្យូទ័រធ្វើការសម្រេចចិត្តប្រហាក់ប្រហែលនឹងការគិតរបស់មនុស្ស ដោយប្រើប្រាស់តម្លៃចន្លោះពី ០ ទៅ ១ (ឧ. កម្រិត "ល្អបង្គួរ" ឬ "អាក្រក់បន្តិច") ជាជាងការប្រើតែតម្លៃដាច់ខាត ០ ឬ ១ (ខុស ឬ ត្រូវ)។ ដូចជាការសារ៉េកម្រិតសំឡេងវិទ្យុ ដែលអ្នកអាចសារ៉េតិច ឬខ្លាំងតាមចំណូលចិត្ត មិនមែនមានតែប៊ូតុង "បិទ" និង "បើក" នោះទេ។
Over-Provisioning ការផ្តល់ ឬបម្រុងទុកធនធានកុំព្យូទ័រ (ដូចជា RAM ឬ CPU) លើសពីតម្រូវការជាក់ស្តែងរបស់អ្នកប្រើប្រាស់ ដែលបណ្តាលឱ្យខ្ជះខ្ជាយធនធាន និងខាតបង់ប្រាក់ចំណេញសម្រាប់អ្នកផ្តល់សេវា។ ដូចជាការជួលឡានក្រុងធំមួយមានកៅអី ៥០ សម្រាប់មនុស្សតែ ៥ នាក់ជិះ ដែលធ្វើឱ្យខាតលុយឥតប្រយោជន៍។
Under-Provisioning ការផ្តល់ធនធានកុំព្យូទ័រតិចជាងតម្រូវការជាក់ស្តែង ដែលបណ្តាលឱ្យប្រព័ន្ធដើរយឺត ឬគាំង និងធ្វើឱ្យប៉ះពាល់ដល់កិច្ចព្រមព្រៀងគុណភាពសេវាកម្ម (SLA) ជាមួយអតិថិជនដែលបានបង់ប្រាក់។ ដូចជាការរៀបចំបាយតែ ៥ ចាន សម្រាប់ភ្ញៀវ ១០ នាក់ ដែលធ្វើឱ្យអ្នកខ្លះមិនបានហូប និងខឹងសម្បារ។
Virtual machine កុំព្យូទ័រនិម្មិតដែលដំណើរការដោយកម្មវិធី (Software) នៅលើកុំព្យូទ័ររូបវន្ត (Physical Computer) តែមួយ ដោយវាមានប្រព័ន្ធប្រតិបត្តិការ (OS) និងកម្មវិធីផ្ទាល់ខ្លួន ដាច់ដោយឡែកពីម៉ាស៊ីនមេ។ ដូចជាការបែងចែកផ្ទះធំមួយជាបន្ទប់ជួលតូចៗជាច្រើន ដែលបន្ទប់នីមួយៗមានទ្វារ និងសោរផ្ទាល់ខ្លួន អាចរស់នៅដោយឯករាជ្យពីគ្នា។
Electronic Medical Record ប្រព័ន្ធរក្សាទុកព័ត៌មាន និងប្រវត្តិជំងឺរបស់អ្នកជំងឺក្នុងទម្រង់ជាឌីជីថល (ឯកសារកុំព្យូទ័រ) ជំនួសឱ្យការកត់ត្រាលើក្រដាស ដើម្បីងាយស្រួលក្នុងការស្វែងរក គ្រប់គ្រង បម្រុងទុក និងរក្សាសុវត្ថិភាពទិន្នន័យ។ ដូចជាសៀវភៅតាមដានសុខភាពដែលប្តូរពីការសរសេរលើក្រដាស មកវាយបញ្ចូល និងរក្សាទុកក្នុងកុំព្យូទ័រ ឬទូរស័ព្ទដៃវិញ។
Quality of service សូចនាករដែលវាស់វែងពីកម្រិតគុណភាព និងស្ថិរភាពនៃសេវាកម្មបណ្តាញ ឬក្លោដ ដូចជាល្បឿននៃប្រតិបត្តិការ ពេលវេលារង់ចាំ និងអត្រាបាត់បង់ទិន្នន័យ ដើម្បីធានាថាអ្នកប្រើប្រាស់ទទួលបានសេវាដែលល្អ និងគួរឱ្យទុកចិត្ត។ ដូចជាការវាយតម្លៃសេវាកម្មរបស់ភោជនីយដ្ឋានមួយ ថាតើគេរៀបចំម្ហូបបានលឿន ឆ្ងាញ់ និងមានអនាម័យកម្រិតណា។
