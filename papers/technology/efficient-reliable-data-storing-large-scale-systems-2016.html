ចំណងជើងដើម៖ Efficient and Reliable Data Storing Methods in Large-scale Storage Systems

អ្នកនិពន្ធ៖ Hiroaki AKUTSU (Waseda University)

ឆ្នាំបោះពុម្ព៖ 2016

វិស័យសិក្សា៖ Computer Science

១. សេចក្តីសង្ខេបប្រតិបត្តិ (Executive Summary)

បញ្ហា (The Problem)៖ ប្រព័ន្ធផ្ទុកទិន្នន័យខ្នាតធំ (Large-scale storage systems) ជួបប្រទះនឹងបញ្ហាប្រឈមទាក់ទងនឹងការធានាភាពជឿជាក់នៃទិន្នន័យ បន្ទុកនៃការបង្កើតទិន្នន័យស្ទួន និងការចាត់ចែងទិន្នន័យក្នុងឧបករណ៍ផ្ទុកចម្រុះប្រភេទ។ និក្ខេបបទនេះផ្តោតលើការដោះស្រាយបញ្ហាទាំងនេះដើម្បីសម្រេចបាននូវការផ្ទុកទិន្នន័យដែលមានប្រសិទ្ធភាពខ្ពស់។

វិធីសាស្ត្រ (The Methodology)៖ ការស្រាវជ្រាវនេះបានបង្កើត និងវាយតម្លៃលើបច្ចេកវិទ្យាស្នូលចំនួនបីសម្រាប់ការគ្រប់គ្រងទិន្នន័យ ដោយប្រើប្រាស់គំរូគណិតវិទ្យា និងការធ្វើត្រាប់តាម (Simulations)។

  • បច្ចេកវិទ្យាផ្ទុកទិន្នន័យបែបបែងចែក (Distributed Data Storing Technology) ដោយប្រើប្រាស់យន្តការស្តារទិន្នន័យ Dynamic Refuging
  • បច្ចេកវិទ្យាផ្ទុកទិន្នន័យក្នុងទីតាំងផ្ទាល់ (Local Placement Data Storing Technology) តាមរយៈការធ្វើកូដនីយកម្ម Multi-stage Erasure Coding (MEC)
  • បច្ចេកវិទ្យាចាត់ថ្នាក់ឧបករណ៍ផ្ទុកដោយស្វ័យប្រវត្តិ (Storage Automated Tiering Technology) ផ្អែកលើកម្រិតញឹកញាប់នៃការចូលប្រើទិន្នន័យ

លទ្ធផលសំខាន់ៗ (The Verdict)៖

  • យន្តការ Dynamic Refuging ជួយកាត់បន្ថយហានិភ័យ និងកំណត់ទីតាំងផលប៉ះពាល់នៃការបាត់បង់ទិន្នន័យបានយ៉ាងមានប្រសិទ្ធភាព ទោះបីជាចំនួនដ្រាយ (Drives) ក្នុងប្រព័ន្ធមានការកើនឡើងក៏ដោយ។
  • ការប្រើប្រាស់ Multi-stage Erasure Coding (MEC) កាត់បន្ថយទំហំទិន្នន័យស្ទួន និងរក្សាបាននូវដំណើរការកម្រិតខ្ពស់ ដោយមិនពឹងផ្អែកលើទំហំទិន្នន័យបញ្ជូន (Communication volume) ពេលសរសេរទិន្នន័យ។
  • ការចាត់ថ្នាក់ទិន្នន័យដោយស្វ័យប្រវត្តិ ដោយផ្តល់អាទិភាពផ្លាស់ទីទិន្នន័យប្រើញឹកញាប់ទៅកាន់ឧបករណ៍លឿន អាចកាត់បន្ថយពេលវេលាឆ្លើយតប I/O ជាមធ្យមបានយ៉ាងជាក់ស្តែង។

២. ការវិភាគលើប្រសិទ្ធភាព និងការចំណាយ (Performance & Constraints)

វិធីសាស្ត្រ (Method) គុណសម្បត្តិ (Pros) គុណវិបត្តិ (Cons) លទ្ធផលគន្លឹះ (Key Result)
Mirroring
ការចម្លងទិន្នន័យ (Mirroring)		 ងាយស្រួលក្នុងការអនុវត្ត និងជួយការពារទិន្នន័យបានល្អក្នុងប្រព័ន្ធ NoSQL។ ទំហំទិន្នន័យស្ទួនកើនឡើងខ្លាំងធ្វើឱ្យខាតបង់ទំហំផ្ទុក (Capacity overhead) ក៏ដូចជាកាត់បន្ថយទំហំប្រើប្រាស់ពិតប្រាកដ។ មិនស័ក្តិសមសម្រាប់ប្រព័ន្ធផ្ទុកទិន្នន័យទំហំធំដោយសារការខាតបង់ទំហំ និងធ្លាក់ចុះដំណើរការ Write ដោយសារកើនឡើងទំហំទិន្នន័យបញ្ជូន។
Standard Parity / Erasure Coding
កូដនីយកម្មលុបបំបាត់ស្តង់ដារ (Standard Erasure Coding)		 ចំណាយទំហំផ្ទុកតិចជាង Mirroring សម្រាប់រក្សាភាពជឿជាក់នៃទិន្នន័យ។ ដំណើរការ Read ធ្លាក់ចុះនៅពេលទិន្នន័យត្រូវបែងចែកឆ្លងកាត់ម៉ាស៊ីនមេ (Servers) ផ្សេងគ្នា។ ដំណើរការអានទិន្នន័យយឺត ជាហេតុមិនសូវត្រូវបានប្រើប្រាស់ជាមួយអង្គចងចាំល្បឿនលឿន (Memory-class storage)។
Dynamic Refuging
យន្តការស្តារទិន្នន័យប្រកបដោយថាមវន្ត (Dynamic Refuging)		 ផ្តោតលើការសង្គ្រោះប្លុកទិន្នន័យដែលមានហានិភ័យខ្ពស់ (Lowest redundancy level) មុនគេ ជួយកាត់បន្ថយហានិភ័យបាត់បង់ទិន្នន័យប្រកបដោយប្រសិទ្ធភាព។ ទាមទារការតាមដានស្ថានភាពដ្រាយស្មុគស្មាញ និងទាមទារការវិភាគតាមរយៈម៉ូដែល Monte Carlo ។ ទោះបីជាចំនួនដ្រាយ (Drives) កើនឡើងយ៉ាងណាក្តី ហានិភ័យនៃការបាត់បង់ទិន្នន័យមិនមានការកើនឡើងនោះទេ (Scale-out without risk increase)។
Multi-stage Erasure Coding (MEC)
កូដនីយកម្មលុបបំបាត់ពហុដំណាក់កាល (MEC)		 កាត់បន្ថយទំហំទិន្នន័យស្ទួន និងរក្សាដំណើរការលឿនដោយមិនពឹងផ្អែកលើទំហំទិន្នន័យបញ្ជូននៅពេលសរសេរទិន្នន័យចូល។ ការរៀបចំ និងការគ្រប់គ្រងកូដមានភាពស្មុគស្មាញដោយប្រើប្រាស់ ២ ដំណាក់កាលផ្សេងគ្នា។ កាត់បន្ថយការប្រើប្រាស់ទំហំផ្ទុក និងអាចដំណើរការបានយ៉ាងមានប្រសិទ្ធភាពលើឧបករណ៍កម្រិតខ្ពស់ដូចជា Flash Memory ឬ SCM។
Automated Tiering with HOL Scheduling
ការចាត់ថ្នាក់ដោយស្វ័យប្រវត្តិជាមួយការកំណត់កាលវិភាគ HOL		 ផ្តល់អាទិភាពដល់ទិន្នន័យដែលប្រើញឹកញាប់ទៅផ្ទុកលើឧបករណ៍លឿន (SSD) ដែលជួយកាត់បន្ថយពេលវេលាឆ្លើយតប។ ទាមទារការតាមដានប្រេកង់នៃការចូលប្រើប្រាស់ទិន្នន័យជានិច្ច ដែលអាចស៊ីធនធានប្រព័ន្ធ (Overhead) មួយចំនួន។ ការប្រើប្រាស់ម៉ូដែលជួររង់ចាំ (Queuing analysis) បង្ហាញថាវិធីសាស្ត្រ HOL កាត់បន្ថយពេលវេលាឆ្លើយតប I/O ជាមធ្យមបានយ៉ាងមានប្រសិទ្ធភាពធៀបនឹងវិធី FCFS ។

ការចំណាយលើធនធាន (Resource Cost)៖ ការអនុវត្តបច្ចេកវិទ្យាទាំងនេះទាមទារហេដ្ឋារចនាសម្ព័ន្ធផ្ទុកទិន្នន័យខ្នាតធំ និងកម្មវិធីគ្រប់គ្រងកម្រិតខ្ពស់។

  • Hardware: ម៉ាស៊ីនមេ (Servers) ច្រើន និងឧបករណ៍ផ្ទុកទិន្នន័យចម្រុះ (SSD, HDD និង SCM - Storage Class Memory) ដែលមានចំនួនរាប់ពាន់ដ្រាយ។
  • Software: កម្មវិធី Software-Defined Storage ដែលមានមុខងារគាំទ្រ Erasure Coding និង Automated Tiering។
  • Expertise: អ្នកជំនាញផ្នែកស្ថាបត្យកម្មប្រព័ន្ធផ្ទុកទិន្នន័យ (Storage Architecture) អ្នកជំនាញគណិតវិទ្យាសម្រាប់វិភាគប្រូបាប៊ីលីតេ (Probability Analysis) និងការធ្វើត្រាប់តាម (Simulation Models)។

៣. ការពិនិត្យសម្រាប់បរិបទកម្ពុជា/អាស៊ីអាគ្នេយ៍

ភាពលំអៀងនៃទិន្នន័យ (Data Bias)៖

ការសិក្សានេះត្រូវបានរចនាឡើង និងធ្វើត្រាប់តាម (Simulated) សម្រាប់មជ្ឈមណ្ឌលទិន្នន័យខ្នាតធំកម្រិតសហគ្រាស (Enterprise-level) ដែលមានដ្រាយរាប់ពាន់នៅក្នុងបរិបទប្រទេសជប៉ុន។ សម្រាប់ប្រទេសកម្ពុជា ទិន្នន័យនេះអាចមានភាពលម្អៀង ដោយសារស្ថាប័នភាគច្រើនមិនទាន់មានទំហំផ្ទុកទិន្នន័យធំធេងដល់កម្រិតរាប់ពាន់ដ្រាយនៅឡើយទេ។ ទោះយ៉ាងណាក៏ដោយ គោលការណ៍កាត់បន្ថយថ្លៃដើម និងការបង្កើនសុវត្ថិភាពទិន្នន័យគឺមានសារៈសំខាន់ខ្លាំងសម្រាប់ការរៀបចំហេដ្ឋារចនាសម្ព័ន្ធទៅថ្ងៃអនាគត។

លទ្ធភាពនៃការអនុវត្ត (Applicability)៖

បច្ចេកវិទ្យានេះមានសារៈសំខាន់សម្រាប់ការអភិវឌ្ឍហេដ្ឋារចនាសម្ព័ន្ធឌីជីថល និងការសាងសង់មជ្ឈមណ្ឌលទិន្នន័យ (Data Centers) នៅក្នុងប្រទេសកម្ពុជា។

  • មជ្ឈមណ្ឌលទិន្នន័យជាតិ (National Data Center): អាចប្រើប្រាស់បច្ចេកវិទ្យា Automated Tiering ដើម្បីសន្សំសំចៃការចំណាយលើការទិញឧបករណ៍ ដោយទុកទិន្នន័យឯកសាររដ្ឋចាស់ៗលើ HDD និងទិន្នន័យពលរដ្ឋដែលត្រូវប្រើញឹកញាប់លើ SSD ។
  • វិស័យធនាគារ និងហិរញ្ញវត្ថុ (ឧទាហរណ៍៖ ACLEDA, ABA): ត្រូវការប្រព័ន្ធ NoSQL ល្បឿនលឿន និងមានសុវត្ថិភាពខ្ពស់ ដូចនេះបច្ចេកវិទ្យា Multi-stage Erasure Coding (MEC) ជួយការពារទិន្នន័យប្រតិបត្តិការហិរញ្ញវត្ថុ (Transactions) ដោយមិនធ្វើឱ្យប្រព័ន្ធដើរយឺត។
  • ក្រុមហ៊ុនទូរគមនាគមន៍ (ឧទាហរណ៍៖ Cellcard, Smart): អាចអនុវត្ត Dynamic Refuging ដើម្បីការពារទិន្នន័យអតិថិជនរាប់លាននាក់ពីការខូចខាត Hardware ដោយប្រព័ន្ធអាចជួសជុលទិន្នន័យដែលមានហានិភ័យខ្ពស់ដោយស្វ័យប្រវត្តិ។

ជាសរុប ការអនុវត្តបច្ចេកវិទ្យាទាំងនេះនឹងជួយស្ថាប័នធំៗនៅកម្ពុជាសន្សំសំចៃថវិកាលើ Hardware ពង្រឹងសុវត្ថិភាពទិន្នន័យ និងត្រៀមខ្លួនរួចរាល់សម្រាប់យុគសម័យទិន្នន័យធំ (Big Data)។

៤. ផែនការសកម្មភាពសម្រាប់និស្សិត (Actionable Roadmap)

ដើម្បីអនុវត្តតាមការសិក្សានេះ និស្សិតគួរអនុវត្តតាមជំហានខាងក្រោម៖

  1. ជំហានទី១៖ សិក្សាពីស្ថាបត្យកម្មប្រព័ន្ធផ្ទុកទិន្នន័យ (Storage Architecture Basics): ចាប់ផ្តើមរៀនអំពី Software-Defined Storage ដោយធ្វើការដំឡើង និងសាកល្បងប្រើប្រាស់ Ceph ឬ TrueNAS នៅក្នុងប្រព័ន្ធសាកល្បង (Virtual Machines) ដើម្បីស្វែងយល់ពីរបៀបដែលទិន្នន័យត្រូវបានចែកចាយ។
  2. ជំហានទី២៖ ស្វែងយល់ពីបច្ចេកវិទ្យា Erasure Coding: សិក្សាពីមូលដ្ឋានគ្រឹះគណិតវិទ្យា (Reed-Solomon) និងសាកល្បងសរសេរកូដអនុវត្តផ្ទាល់តាមរយៈបណ្ណាល័យ Jerasure ឬ Intel ISA-L ដើម្បីយល់ពីរបៀបដែល Parity ធ្វើការការពារទិន្នន័យ។
  3. ជំហានទី៣៖ អនុវត្តការចាត់ថ្នាក់ទិន្នន័យដោយស្វ័យប្រវត្តិ (Data Tiering): អនុវត្តការរៀបចំ Storage Tiering នៅលើប្រព័ន្ធប្រតិបត្តិការ Linux ដោយប្រើប្រាស់ឧបករណ៍ដូចជា bcache ឬ lvmcache ដើម្បីសាកល្បងបញ្ចូលគ្នាផ្ទាល់រវាង SSD ល្បឿនលឿន និង HDD ចំណុះធំ។
  4. ជំហានទី៤៖ ការធ្វើត្រាប់តាម និងការវាស់ស្ទង់ប្រសិទ្ធភាព (Simulation & Benchmarking): ប្រើប្រាស់ឧបករណ៍វាស់ស្ទង់ដូចជា fio សម្រាប់ Linux ដើម្បីធ្វើតេស្តល្បឿន I/O និងប្រៀបធៀបពេលវេលាឆ្លើយតប (Response Time) រវាងប្រព័ន្ធដែលមានការតំរៀបជាជួរ FCFS និងប្រព័ន្ធដែលមាន Tiering។
  5. ជំហានទី៥៖ សិក្សាពីការចែកចាយទិន្នន័យលើ NoSQL ធំៗ: បង្កើតមូលដ្ឋានទិន្នន័យ NoSQL ដូចជា Apache Cassandra ឬ MongoDB ហើយធ្វើតេស្តការគ្រប់គ្រងម៉ាស៊ីនមេ (Node Failures) ដើម្បីស្វែងយល់ពីរបៀបស្តារទិន្នន័យ (Rebuilding process) ក្នុងបរិស្ថានជាក់ស្តែង។

៥. វាក្យសព្ទបច្ចេកទេស (Technical Glossary)

ពាក្យបច្ចេកទេស (English) ការពន្យល់ជាខេមរភាសា (Khmer Explanation) និយមន័យសាមញ្ញ (Simple Definition)
Dynamic Refuging ជាយន្តការមួយនៅក្នុងប្រព័ន្ធផ្ទុកទិន្នន័យបែងចែក ដែលផ្តល់អាទិភាពក្នុងការជួសជុល (Rebuild) ប្លុកទិន្នន័យណាដែលមានកម្រិតទិន្នន័យស្ទួន (Redundancy) ទាបជាងគេមុនគេ ដើម្បីកាត់បន្ថយហានិភ័យនៃការបាត់បង់ទិន្នន័យនៅពេលមានថាសរឹង (Drive) ខូចច្រើនក្នុងពេលតែមួយ។ ដូចជាការជួយសង្គ្រោះអ្នកជំងឺដែលមានអាការៈធ្ងន់ធ្ងរជាងគេមុន នៅក្នុងបន្ទប់សង្គ្រោះបន្ទាន់ ដើម្បីធានាអាយុជីវិតពួកគេ។
Erasure Coding ជាវិធីសាស្ត្រការពារទិន្នន័យដោយបំបែកទិន្នន័យជាចំណែកតូចៗ ហើយបង្កើតកូដបន្ថែម (Parity) រួចចែកចាយវាទៅកាន់ម៉ាស៊ីនផ្សេងៗគ្នា។ បើមានម៉ាស៊ីនណាមួយខូច ទិន្នន័យដើមនៅតែអាចទាញយកមកវិញបានដោយប្រើចំណែកទិន្នន័យដែលនៅសល់រួមជាមួយកូដបន្ថែមនោះ។ ដូចជាការសរសេរសំបុត្រមួយច្បាប់ រួចកាត់វាជា ៣ ចំណែក ហើយថតចម្លងបំណែកបម្រុងទុក ដូច្នេះទោះបីជាបាត់បំណែកណាមួយ ក៏នៅតែអាចផ្គុំសំបុត្រនោះឡើងវិញបាន។
Multi-stage Erasure Coding ជាការកែលម្អលើ Erasure Coding ធម្មតា ដោយដំណើរការសរសេរកូដ (Encoding) ជាពីរដំណាក់កាលផ្សេងគ្នា (នៅខាងម៉ាស៊ីនបញ្ជូន និងម៉ាស៊ីនទទួល) ដើម្បីកាត់បន្ថយទំហំទិន្នន័យស្ទួន និងកាត់បន្ថយបន្ទុកបញ្ជូនទិន្នន័យតាមបណ្តាញ (Network Overhead) កំឡុងពេលសរសេរទិន្នន័យចូល។ ដូចជាការវេចខ្ចប់ទំនិញជាប្រអប់តូចៗពីផ្ទះ រួចយកទៅដាក់ក្នុងទូកុងតឺន័រធំនៅកំពង់ផែ ដើម្បីងាយស្រួលនិងចំណេញកន្លែងក្នុងការដឹកជញ្ជូន។
Storage Automated Tiering ជាបច្ចេកវិទ្យាដែលរៀបចំ និងផ្លាស់ទីទិន្នន័យដោយស្វ័យប្រវត្តិរវាងឧបករណ៍ផ្ទុកទិន្នន័យដែលមានល្បឿន និងតម្លៃខុសៗគ្នា (ឧទាហរណ៍ ពី HDD ទៅ SSD) ដោយផ្អែកលើភាពញឹកញាប់នៃការប្រើប្រាស់ ដើម្បីបង្កើនល្បឿន និងសន្សំសំចៃថវិកា។ ដូចជាការរៀបចំទំនិញក្នុងហាង ដោយដាក់ទំនិញលក់ដាច់បំផុតនៅខាងមុខងាយស្រួលយក និងទំនិញមិនសូវលក់ដាច់នៅក្នុងឃ្លាំងខាងក្រោយ។
HOL តំណាងឱ្យ Head-of-Line ដែលជាប្រព័ន្ធកំណត់កាលវិភាគបញ្ជូនទិន្នន័យ (Scheduling) ដែលផ្តល់អាទិភាពដល់កញ្ចប់ទិន្នន័យសំខាន់ៗ ឬទិន្នន័យដែលត្រូវប្រើបន្ទាន់ឱ្យបានដំណើរការមុនទិន្នន័យធម្មតា ជួយកាត់បន្ថយភាពរាំងស្ទះ និងបង្កើនល្បឿនឆ្លើយតប។ ដូចជាការអនុញ្ញាតឱ្យរថយន្តសង្គ្រោះបន្ទាន់ ឬរថយន្ត VIP អាចបើកបរវ៉ាជួររថយន្តធម្មតានៅស្តុប ដើម្បីទៅដល់គោលដៅបានលឿន។
FCFS តំណាងឱ្យ First-Come First-Served ដែលជាយន្តការមូលដ្ឋានក្នុងការចាត់ចែងដំណើរការ (I/O) ដែលសំណើ (Requests) ទិន្នន័យណាដែលមកដល់មុន នឹងត្រូវបានដំណើរការមុនតាមលំដាប់ជួរ ដោយគ្មានការផ្តល់អាទិភាពពិសេសឡើយ។ ដូចជាការតម្រង់ជួរទិញសំបុត្រកុន អ្នកដែលមកឈរតម្រង់ជួរមុន នឹងបានទិញសំបុត្រមុន។
NoSQL ជាប្រភេទមូលដ្ឋានទិន្នន័យ (Database) ដែលមិនប្រើប្រាស់ទម្រង់តារាងទំនាក់ទំនង (Relational Tabular format) ដូច SQL ធម្មតា។ វាត្រូវបានរចនាឡើងដើម្បីផ្ទុកទិន្នន័យដែលមិនមានរចនាសម្ព័ន្ធច្បាស់លាស់ច្រើនសន្ធឹកសន្ធាប់ និងអាចពង្រីកទំហំម៉ាស៊ីនមេបានយ៉ាងងាយស្រួល (Scalability)។ ដូចជាការទុកឯកសារក្នុងទូដោយដាក់តាមថតក្រដាស ឬប្រអប់ផ្សេងៗគ្នា (ឯកសាររូបភាព, ឯកសារអត្ថបទ) ជំនួសឱ្យការកត់ត្រាចូលក្នុងសៀវភៅបញ្ជីដែលមានក្រឡាតឹងរ៉ឹងតែមួយ។
Monte Carlo simulation ជាវិធីសាស្ត្រគណិតវិទ្យាដែលប្រើប្រាស់ការបង្កើតទិន្នន័យចៃដន្យ (Random Sampling) ជាច្រើនដង ដើម្បីវាយតម្លៃហានិភ័យ និងវិភាគប្រូបាប៊ីលីតេនៃព្រឹត្តិការណ៍ស្មុគស្មាញ (ក្នុងន័យនេះគឺការព្យាករណ៍ពីការខូចខាតថាសរឹងក្នុងប្រព័ន្ធផ្ទុកទិន្នន័យ)។ ដូចជាការទម្លាក់គ្រាប់ឡុកឡាក់រាប់ពាន់ដង ដើម្បីកត់ត្រា និងទស្សន៍ទាយថាតើលេខមួយណានឹងចេញច្រើនជាងគេ។
