១. សេចក្តីសង្ខេបប្រតិបត្តិ (Executive Summary)

បញ្ហា (The Problem)៖ ឧបករណ៍ផ្ទុកទិន្នន័យប្រភេទ HDD កំពុងឈានដល់ដែនកំណត់ផ្នែករូបវិទ្យា (superparamagnetic limit) ដែលតម្រូវឱ្យមានបច្ចេកវិទ្យាថ្មីដូចជា Shingled Magnetic Recording (SMR) ដើម្បីបង្កើនទំហំផ្ទុក ប៉ុន្តែវាធ្វើឱ្យបាត់បង់សមត្ថភាពសរសេរទិន្នន័យដោយចៃដន្យ (random-write)។ ការស្រាវជ្រាវនេះដោះស្រាយបញ្ហាភាពស៊ីគ្នានៃ SMR ជាមួយនឹងប្រព័ន្ធទិន្នន័យធំៗ (Big Data) ដែលត្រូវការទំហំផ្ទុកធំនិងតម្លៃថោក។

វិធីសាស្ត្រ (The Methodology)៖ អ្នកស្រាវជ្រាវបានបង្កើតកម្មវិធីត្រាប់តាមឧបករណ៍ SMR និងប្រព័ន្ធឯកសារថ្មីមួយឈ្មោះថា ShingledFS ផ្អែកលើ FUSE ដើម្បីវាយតម្លៃដំណើរការនៃបន្ទុកការងារធំៗនៅលើប្រព័ន្ធ SMR ។

  • ការអភិវឌ្ឍកម្មវិធីត្រាប់តាមឧបករណ៍ (SMR Device Emulator) ដោយផ្អែកលើសំណុំពាក្យបញ្ជាស្តង់ដារ T13 Banded Device Command Set
  • ការរចនាប្រព័ន្ធឯកសារដឹងពី SMR (SMR-aware file system - ShingledFS) ដែលដំណើរការក្នុងទំហំអ្នកប្រើប្រាស់ (User-space) តាមរយៈ FUSE
  • ការវាយតម្លៃដំណើរការប្រព័ន្ធដោយប្រើប្រាស់បន្ទុកការងារ Hadoop/HDFS (ដូចជា TeraGen, TeraSort និង TeraValidate)

លទ្ធផលសំខាន់ៗ (The Verdict)៖

  • វិធីសាស្ត្រដ៏ប្រសើរបំផុតដើម្បីគាំទ្រឧបករណ៍ SMR គឺការរុញភាពឆ្លាតវៃចូលទៅក្នុងប្រព័ន្ធឯកសារ (Type-II SMR) ជាជាងការប្រើប្រាស់ស្រទាប់បកប្រែ (Shim layer/Type-I SMR)។
  • បន្ទុកការងាររបស់កម្មវិធី Big Data អាចដំណើរការយ៉ាងរលូននៅលើប្រព័ន្ធ SMR ជាមួយនឹងកម្រិតបន្ទុកបន្ថែម (Overhead) ទាបបំផុតរហូតដល់ត្រឹម ២.២% បន្ទាប់ពីកាត់ចេញនូវបន្ទុកនៃកម្មវិធីត្រាប់តាម។
  • យន្តការសម្អាតទិន្នន័យឥតបានការ (Garbage collection) មានសារៈសំខាន់ណាស់ ដោយការបោសសម្អាតទិន្នន័យចាស់ៗពីចុងបញ្ចប់នៃកម្រង (Tail cleaning) ផ្តល់នូវចំណេញទំហំផ្ទុកខ្ពស់បំផុតធៀបនឹងការប្រឹងប្រែងផ្លាស់ទីទិន្នន័យ។

២. ការវិភាគលើប្រសិទ្ធភាព និងដែនកំណត់ (Performance & Constraints)

វិធីសាស្ត្រ (Method) គុណសម្បត្តិ (Pros) គុណវិបត្តិ (Cons) លទ្ធផលគន្លឹះ (Key Result)
Traditional HDD (ext3)
ថាសរឹងប្រពៃណី (ext3)		 ដំណើរការសរសេរទិន្នន័យដោយចៃដន្យ (Random writes) បានលឿន និងជាស្តង់ដារទូទៅដែលមិនមានបន្ទុកបន្ថែមពីកម្មវិធីកម្រិតកណ្តាល។ កំពុងឈានដល់ដែនកំណត់ផ្នែករូបវិទ្យានៃទំហំផ្ទុកអតិបរមា និងមានតម្លៃថ្លៃជាងក្នុងមួយតេរ៉ាបៃបើធៀបនឹង SMR។ ដើរតួជាកម្រិតគោល (Baseline) សម្រាប់ការប្រៀបធៀបដំណើរការ ដែលផ្តល់ល្បឿនលឿនជាងគេបំផុតសម្រាប់បន្ទុកការងារទូទៅ។
FUSE File System
ប្រព័ន្ធឯកសារ FUSE		 ងាយស្រួលក្នុងការអភិវឌ្ឍ និងសាកល្បងប្រព័ន្ធឯកសារថ្មីៗនៅក្នុងទំហំអ្នកប្រើប្រាស់ (User-space) ដោយមិនប៉ះពាល់ដល់ខឺណែល (Kernel)។ បង្កើតបន្ទុកបន្ថែម (Overheads) ដោយសារការផ្លាស់ប្តូរម៉ូដប្រតិបត្តិការច្រើនដង និងទម្លាប់បំបែកការសរសេរទិន្នន័យធំៗជាកង់តូចៗ (4KB)។ ដំណើរការយឺតជាងប្រព័ន្ធ ext3 បន្តិច ប៉ុន្តែបន្ទុកបន្ថែមនេះថយចុះនៅពេលទំហំទិន្នន័យកើនឡើងកាន់តែធំ។
SMR Emulator + ShingledFS
កម្មវិធីត្រាប់ SMR និង ShingledFS		 អាចផ្តល់ទំហំផ្ទុកធំ និងអាចដំណើរការទិន្នន័យធំៗដែលមានលក្ខណៈសរសេរជាលំដាប់ (Sequential) បានយ៉ាងមានប្រសិទ្ធភាព។ មានដំណើរការយឺតខ្លាំងចំពោះការសរសេរទិន្នន័យតូចៗដោយចៃដន្យ (ឧ. ការពន្លាឯកសារ untar យឺតជាង ៥៥៥%) និងទាមទារឱ្យមានយន្តការសម្អាតទិន្នន័យ។ សម្រេចបាននូវកម្រិតបន្ទុកបន្ថែមត្រឹមតែ ២.២% ទៅ ៤.៣៤% ប៉ុណ្ណោះសម្រាប់បន្ទុកការងារទិន្នន័យធំៗ (Hadoop) ធៀបនឹង FUSE ធម្មតា។

ការចំណាយលើធនធាន (Resource Cost)៖ ការរៀបចំប្រព័ន្ធសាកល្បងនេះតម្រូវឱ្យមានហេដ្ឋារចនាសម្ព័ន្ធកុំព្យូទ័រជាចង្កោម (Cluster) និងចំណេះដឹងស៊ីជម្រៅផ្នែកប្រព័ន្ធប្រតិបត្តិការ។

  • Hardware: ចង្កោមកុំព្យូទ័រ (Cluster) ចំនួន ៦ គ្រឿងដែលមាន RAM 8GB និង HDD 2TB ភ្ជាប់គ្នាតាមរយៈបណ្តាញល្បឿនលឿន Gigabit Ethernet។
  • Software: ប្រព័ន្ធប្រតិបត្តិការ Linux Ubuntu, ឧបករណ៍ FUSE សម្រាប់បង្កើតប្រព័ន្ធឯកសារ និងប្រព័ន្ធ Hadoop/HDFS កំណែ 0.20.2។
  • Expertise: ចំណេះដឹងផ្នែក Systems Programming ជាមួយនឹងភាសា C/C++ ដើម្បីអភិវឌ្ឍកម្មវិធីត្រាប់ (Emulator) និងស្ថាបត្យកម្មប្រព័ន្ធឯកសារ។

៣. ការពិនិត្យសម្រាប់បរិបទកម្ពុជា/អាស៊ីអាគ្នេយ៍

ភាពលំអៀងនៃទិន្នន័យ (Data Bias)៖

ការសិក្សានេះពឹងផ្អែកលើទិន្នន័យសិប្បនិម្មិតដែលបង្កើតដោយកម្មវិធីវាយតម្លៃ (Hadoop TeraSort និង Linux Kernel Compilation) នៅលើប្រព័ន្ធកុំព្យូទ័ររបស់សាកលវិទ្យាល័យ Carnegie Mellon នៅសហរដ្ឋអាមេរិក។ ទោះបីជាវាមិនមានភាពលម្អៀងផ្នែកភូមិសាស្ត្រ ប៉ុន្តែលទ្ធផលនេះផ្តោតខ្លាំងតែលើបន្ទុកការងារដែលមានការសរសេរជាលំដាប់ (Sequential Writes) ធំៗប៉ុណ្ណោះ។ ចំណុចនេះមានសារៈសំខាន់ណាស់សម្រាប់អ្នកបច្ចេកទេសនៅកម្ពុជា ព្រោះការជ្រើសរើស SMR យកទៅប្រើប្រុសខុសគោលដៅ (ឧទាហរណ៍ សម្រាប់ Database ដែលមានការកែប្រែទិន្នន័យចៃដន្យច្រើន) នឹងធ្វើឱ្យប្រព័ន្ធគាំង ឬយឺតយ៉ាវយ៉ាងខ្លាំង។

លទ្ធភាពនៃការអនុវត្ត (Applicability)៖

បច្ចេកវិទ្យា SMR និងវិធីសាស្ត្រកែច្នៃប្រព័ន្ធឯកសារនេះមានប្រយោជន៍ខ្លាំងសម្រាប់ស្ថាប័ននៅកម្ពុជា ដែលត្រូវការទំហំផ្ទុកទិន្នន័យដ៏ធំមហិមាក្នុងតម្លៃថោក។

  • Data Centers & ISPs: មជ្ឈមណ្ឌលទិន្នន័យ និងក្រុមហ៊ុនផ្តល់សេវាអ៊ីនធឺណិត (ISP) នៅកម្ពុជា អាចប្រើប្រាស់ថាសរឹង SMR សម្រាប់ផ្ទុកកំណត់ត្រាទិន្នន័យបណ្តាញ (Log files) និងប្រវត្តិប្រតិបត្តិការណ៍ផ្សេងៗក្នុងតម្លៃទាប។
  • Government IT Systems: ក្រសួងស្ថាប័នរដ្ឋ អាចប្រើប្រាស់ SMR សម្រាប់ប្រព័ន្ធបម្រុងទុកទិន្នន័យជាតិ (National Backup Systems) ដែលទាមទារលក្ខណៈសរសេរចូលម្ដង និងអានច្រើនដង (Write-Once-Read-Many) សម្រាប់ទុកជាឯកសារយោង។
  • University Research & Big Data: សាកលវិទ្យាល័យអាចប្រើប្រាស់វាដើម្បីបង្កើតឃ្លាំងទិន្នន័យធំៗ (Data Lakes) គាំទ្រដល់ការសិក្សាស្រាវជ្រាវផ្នែក AI និង Machine Learning ដោយកាត់បន្ថយចំណាយលើ Hardware។

ការយល់ដឹងពីចំណុចខ្លាំងនិងចំណុចខ្សោយរបស់ឧបករណ៍ SMR អនុញ្ញាតឱ្យស្ថាប័ននៅកម្ពុជាអាចរៀបចំយុទ្ធសាស្ត្រផ្ទុកទិន្នន័យប្រកបដោយប្រសិទ្ធភាពខ្ពស់ និងសន្សំសំចៃការចំណាយបានយ៉ាងច្រើន។

៤. ផែនការសកម្មភាពសម្រាប់និស្សិត (Actionable Roadmap)

ដើម្បីអនុវត្តតាមការសិក្សានេះ និស្សិតគួរអនុវត្តតាមជំហានខាងក្រោម៖

  1. សិក្សាមូលដ្ឋានគ្រឹះនៃឧបករណ៍ផ្ទុកទិន្នន័យ: ស្វែងយល់ពីភាពខុសគ្នារវាងស្ថាបត្យកម្ម HDD ប្រពៃណី និង SMR ព្រមទាំងរចនាសម្ព័ន្ធរបស់ប្រព័ន្ធឯកសារដូចជា ext4 និងប្រភេទ Log-structured file systems។
  2. អនុវត្តការអភិវឌ្ឍប្រព័ន្ធឯកសារជាមួយ FUSE: រៀនសរសេរកូដបង្កើតប្រព័ន្ធឯកសារផ្ទាល់ខ្លួននៅក្នុង User-space ដោយប្រើប្រាស់បណ្ណាល័យ libfuse ជាមួយភាសា C ឬ Python ដើម្បីយល់ពីរបៀបចាប់យកកិច្ចហៅប្រព័ន្ធ (VFS System Calls)។
  3. រៀបចំប្រព័ន្ធ Hadoop និង HDFS: តំឡើង និងកំណត់រចនាសម្ព័ន្ធចង្កោម Hadoop ខ្នាតតូច ដើម្បីស្វែងយល់ពីរបៀបដែល HDFS បំបែក និងរក្សាទុកទិន្នន័យជាចំណែកធំៗ (Chunks) ដែលស័ក្តិសមជាមួយ SMR។
  4. អភិវឌ្ឍក្បួនដោះស្រាយសម្រាប់ Garbage Collection: ស្រាវជ្រាវ និងសាកល្បងសរសេរក្បួនដោះស្រាយសម្រាប់សម្អាតទិន្នន័យចាស់ៗចោល (Garbage Collection) ដោយផ្តោតលើវិធីសាស្ត្រ Tail Cleaning ដើម្បីបង្កើនទំហំទំនេរប្រកបដោយប្រសិទ្ធភាព។
  5. វាយតម្លៃប្រព័ន្ធដោយប្រើប្រាស់ឧបករណ៍ Benchmarking: ប្រើប្រាស់ឧបករណ៍វាយតម្លៃកម្រិតស្តង់ដារដូចជា TeraGen, TeraSort និង TeraValidate ដើម្បីវាស់ស្ទង់ល្បឿន និងបន្ទុកការងារនៃប្រព័ន្ធផ្ទុកទិន្នន័យដែលបានបង្កើត។

៥. វាក្យសព្ទបច្ចេកទេស (Technical Glossary)

ពាក្យបច្ចេកទេស ការពន្យល់ជាខេមរភាសា (Khmer Explanation) និយមន័យសាមញ្ញ (Simple Definition)
Shingled Magnetic Recording (SMR) បច្ចេកវិទ្យាផ្ទុកទិន្នន័យលើថាសរឹង (HDD) ដែលបង្កើនទំហំផ្ទុកដោយការសរសេរគន្លងទិន្នន័យ (tracks) ត្រួតស៊ីគ្នាទៅវិញទៅមកមួយផ្នែក ជំនួសឱ្យការដាក់ទន្ទឹមគ្នា។ ការរៀបចំបែបនេះជួយបង្កើនទំហំផ្ទុកបានច្រើន ប៉ុន្តែធ្វើឱ្យការសរសេរ ឬកែប្រែទិន្នន័យកណ្តាលទី (random write) មានភាពស្មុគស្មាញ ព្រោះវាអាចលុបជាន់លើទិន្នន័យនៅគន្លងបន្ទាប់។ ដូចជាការប្រក់ក្បឿងដំបូលផ្ទះដែលសន្លឹកក្បឿងនីមួយៗត្រួតស៊ីគ្នាដើម្បីសន្សំទំហំទីតាំង ខុសពីការក្រាលការ៉ូដែលស្មើៗគ្នា។
Superparamagnetic limit ដែនកំណត់ខាងរូបវិទ្យានៃបច្ចេកវិទ្យាកត់ត្រាម៉ាញ៉េទិច ដែលនៅពេលទំហំផ្ទុកទិន្នន័យ (bit) ត្រូវបានបង្រួមតូចពេក វានឹងងាយរងឥទ្ធិពលកម្ដៅ ដែលធ្វើឱ្យទិន្នន័យអាចបាត់បង់ ឬប្រែប្រួលតម្លៃដោយឯកឯង (thermal self-erasure)។ ដូចជាការសរសេរអក្សរតូចៗពេកនៅលើក្រដាសសើម ដែលធ្វើឱ្យទឹកថ្នាំរាលចូលគ្នាជោកជាំ និងមិនអាចអានដឹងថាជាអក្សរអ្វី។
Write-amplification បាតុភូតដែលការបញ្ជាសរសេរទិន្នន័យតូចមួយចូលទៅក្នុងប្រព័ន្ធផ្ទុកទិន្នន័យ បង្ខំឱ្យប្រព័ន្ធនោះត្រូវអាន លុប និងសរសេរទិន្នន័យក្នុងទំហំមួយយ៉ាងធំត្រលប់មកវិញ (read-modify-write) ព្រោះមិនអាចកែប្រែត្រង់ចំណុចតូចនោះដោយផ្ទាល់បាន ជាពិសេសនៅក្នុងឧបករណ៍ SMR ឬ SSD។ ដូចជាការចង់កែពាក្យខុសតែមួយម៉ាត់នៅក្នុងសៀវភៅ ប៉ុន្តែអ្នកត្រូវសរសេរចម្លងអត្ថបទទាំងមូលក្នុងទំព័រនោះឡើងវិញទាំងអស់។
FUSE (Filesystem in Userspace) ចំណុចប្រទាក់ (Interface) សម្រាប់ប្រព័ន្ធប្រតិបត្តិការ (ដូចជា Linux) ដែលអនុញ្ញាតឱ្យអ្នកប្រើប្រាស់ធម្មតាអាចអភិវឌ្ឍនិងបង្កើតប្រព័ន្ធឯកសារផ្ទាល់ខ្លួនបាន ដោយមិនចាំបាច់ត្រូវការសិទ្ធិខ្ពស់ ឬសរសេរកូដកែប្រែក្នុងកម្រិតខឺណែល (Kernel-level) នោះទេ។ ដូចជាការអនុញ្ញាតឱ្យអ្នកជួលផ្ទះអាចរៀបចំតុបតែងបន្ទប់គេងផ្ទាល់ខ្លួនតាមចិត្ត ដោយមិនចាំបាច់សុំច្បាប់អនុញ្ញាតកែប្រែរចនាសម្ព័ន្ធពីម្ចាស់ផ្ទះ ឬរដ្ឋអំណាចឡើយ។
Garbage Collection ដំណើរការដោយស្វ័យប្រវត្តិក្នុងប្រព័ន្ធឯកសារ (File Systems) ឬឧបករណ៍ផ្ទុកទិន្នន័យ ក្នុងការស្វែងរក ប្រមូល និងបោសសម្អាតទិន្នន័យដែលលែងប្រើ (dead data) ដើម្បីទាញយកទំហំផ្ទុកទំនេរមកប្រើប្រាស់ជាថ្មីឡើងវិញ ដោយរៀបចំទិន្នន័យល្អៗឱ្យនៅផ្ដុំគ្នា។ ដូចជាបុគ្គលិកអនាម័យដែលដើរប្រមូលចានសល់ៗ និងសម្អាតតុនៅក្នុងភោជនីយដ្ឋាន ដើម្បីទុកកន្លែងទំនេរឱ្យភ្ញៀវថ្មីមកអង្គុយបាន។
Perpendicular Magnetic Recording (PMR) បច្ចេកវិទ្យាកត់ត្រាទិន្នន័យដោយតម្រៀបបន្ទាត់ម៉ាញ៉េទិចបញ្ឈរចូលទៅក្នុងផ្ទៃថាស ជំនួសឱ្យការដាក់ផ្ដេក (Longitudinal Recording) ដែលវិធីនេះជួយបង្កើនដង់ស៊ីតេនៃការផ្ទុកទិន្នន័យបានច្រើនជាងមុននៅលើថាសរឹងប្រពៃណី។ ដូចជាការតម្រៀបសៀវភៅបញ្ឈរចូលក្នុងទូ ដែលអាចដាក់សៀវភៅចូលបានច្រើនជាងការតម្រៀបផ្ដេកគរលើគ្នា។
Log-structured file systems ប្រភេទនៃប្រព័ន្ធឯកសារដែលសរសេរទិន្នន័យ និងព័ត៌មានកែប្រែថ្មីៗទាំងអស់បន្តបន្ទាប់គ្នាជាខ្សែតែមួយ (sequential log) ជំនួសឱ្យការសរសេរត្រួតពីលើទីតាំងចាស់ ដែលវាស័ក្តិសមបំផុតសម្រាប់ប្រព័ន្ធដែលពិបាកក្នុងការសរសេរដោយចៃដន្យ (random writes) ដូចជាបច្ចេកវិទ្យា SMR នេះឯង។ ដូចជាការសរសេរកំណត់ហេតុប្រចាំថ្ងៃ ដែលអ្នកគ្រាន់តែសរសេរនៅទំព័របន្តបន្ទាប់គ្នាជារៀងរាល់ថ្ងៃ ជាជាងការត្រលប់ទៅលុប និងសរសេរជាន់លើទំព័រចាស់ៗ។
Inode រចនាសម្ព័ន្ធទិន្នន័យមួយនៅក្នុងប្រព័ន្ធឯកសារ (File System) ដែលផ្ទុកព័ត៌មានលម្អិត (metadata) អំពីឯកសារនីមួយៗ ដូចជាទំហំ ទីតាំងពិតប្រាកដនៅលើថាស សិទ្ធិអ្នកប្រើប្រាស់ និងកាលបរិច្ឆេទនៃការកែប្រែ ជាជាងការផ្ទុកសាច់ទិន្នន័យនៃឯកសារនោះផ្ទាល់។ ដូចជាកាតាឡុកបញ្ជីឈ្មោះសៀវភៅក្នុងបណ្ណាល័យ ដែលប្រាប់ថាចង់រកសៀវភៅនេះ តើត្រូវទៅធ្នើរលេខប៉ុន្មាន ជួរណា ប៉ុន្តែវាមិនមែនជាតួសៀវភៅនោះទេ។
