១. សេចក្តីសង្ខេបប្រតិបត្តិ (Executive Summary)

បញ្ហា/ប្រធានបទ (The Problem/Topic)៖ របាយការណ៍នេះដោះស្រាយបញ្ហាប្រឈមក្នុងការច្របាច់បញ្ចូលឯកសារ shapefile គម្របដី CORINE ចំនួន ៤៤ ដែលមានកំណត់ត្រាជាង ២ លាន ទៅជាសំណុំទិន្នន័យអឺរ៉ុបរួមតែមួយ ដើម្បីសម្រួលដល់ការវិភាគបរិស្ថាន។

វិធីសាស្ត្រ (Approach)៖ ការសិក្សានេះបង្ហាញពីវិធីសាស្ត្រចំនួនពីរក្នុងការរៀបចំសំណុំទិន្នន័យភូមិសាស្ត្រខ្នាតធំដោយប្រើប្រាស់ប្រព័ន្ធព័ត៌មានវិទ្យាភូមិសាស្ត្រ (GIS) និងមូលដ្ឋានទិន្នន័យសាជីវកម្ម។

  • ការប្រើប្រាស់បណ្ណាល័យ ArcINFO ជាមួយម៉ូដែលតូប៉ូឡូស៊ី (ArcINFO Librarian with topological model) ដើម្បីបង្រួមទំហំទិន្នន័យ
  • ការផ្ទុកទិន្នន័យក្នុងមូលដ្ឋានទិន្នន័យ Oracle Spatial (Oracle Spatial database storage) ដោយបំបែកពហុកោណធំៗ
  • ការបំពេញចន្លោះទិន្នន័យ (Data gap filling) ដោយប្រើប្រាស់ និងត្រួតស៊ីគ្នានូវកំណែទិន្នន័យឆ្នាំចាស់ៗ

សេចក្តីសន្និដ្ឋានសំខាន់ៗ (Key Conclusions)៖

  • ការប្រើប្រាស់ម៉ូដែលតូប៉ូឡូស៊ី ArcINFO កាត់បន្ថយទំហំផ្ទុកទិន្នន័យពី ៥.១១ ហ្គីហ្គាបៃ មកត្រឹម ៣.៤៦ ហ្គីហ្គាបៃ ដោយសារព្រំដែនជាប់គ្នាត្រូវបានរក្សាទុកតែម្តង។
  • ការផ្ទុកទិន្នន័យទៅកាន់ Oracle Spatial តម្រូវឱ្យមានការបំបែកពហុកោណធំៗជាក្រឡាចត្រង្គទំហំ ១០០x១០០ គីឡូម៉ែត្រ ដើម្បីជៀសវាងការលើសដែនកំណត់កំណត់ត្រារបស់ប្រព័ន្ធប្រព័ន្ធ។
  • ការស្នើឱ្យចែករំលែកទិន្នន័យគម្របដី CORINE ជាក្រឡា (Tiles) ដែលមានតូប៉ូឡូស៊ី នឹងជួយកាត់បន្ថយទំហំទាញយកបានប្រមាណ ៤០% សម្រាប់អ្នកប្រើប្រាស់។

២. ការរកឃើញសំខាន់ៗ (Key Findings)

របាយការណ៍នេះបង្ហាញពីប្រសិទ្ធភាពនៃការប្រើប្រាស់ប្រព័ន្ធមូលដ្ឋានទិន្នន័យ (Corporate Database) និងកម្មវិធី GIS ដែលមានទម្រង់តូប៉ូឡូស៊ី (Topological format) ដើម្បីបង្រួមទំហំសំណុំទិន្នន័យគម្របដីដែលមានទំហំធំ និងកាត់បន្ថយភាពស្ទួននៃទិន្នន័យ។ ការអនុវត្តបច្ចេកទេសបំបែកទិន្នន័យ (Tiling) ក៏ជួយដោះស្រាយបញ្ហាដែនកំណត់នៃប្រព័ន្ធក្នុងការដំណើរការទិន្នន័យភូមិសាស្ត្រស្មុគស្មាញផងដែរ។

ការរកឃើញ (Finding) ព័ត៌មានលម្អិត (Detail) ភស្តុតាង (Evidence)
ការកាត់បន្ថយទំហំផ្ទុកទិន្នន័យដោយម៉ូដែលតូប៉ូឡូស៊ី (Storage reduction using Topology) ការប្រើប្រាស់ម៉ូដែលតូប៉ូឡូស៊ីរបស់ ArcINFO ជួយសន្សំសំចៃទំហំផ្ទុកបានយ៉ាងច្រើនដោយសារព្រំដែនរួមគ្នារវាងពហុកោណ (Polygons) ត្រូវបានរក្សាទុកតែម្តងប៉ុណ្ណោះ ផ្ទុយពីឯកសារ Shapefile ធម្មតាដែលរក្សាទុកទិន្នន័យត្រួតគ្នា។ ការអនុវត្តវិធីសាស្ត្រនេះបានកាត់បន្ថយទំហំផ្ទុកទិន្នន័យពី ៥.១១ ហ្គីហ្គាបៃ (GB) មកត្រឹម ៣.៤៦ ហ្គីហ្គាបៃ (GB)។
បញ្ហាប្រឈមនៃពហុកោណទំហំធំក្នុងមូលដ្ឋានទិន្នន័យ (Large polygon limits in Databases) ការបញ្ជូនឯកសារចូលទៅកាន់ Oracle Spatial បានជួបប្រទះដែនកំណត់របស់ប្រព័ន្ធនៅពេលជួបពហុកោណធំៗ និងស្មុគស្មាញ (មានរន្ធច្រើន) ដែលតម្រូវឱ្យមានការបំបែកជាក្រឡាតូចៗទំហំ ១០០x១០០ គីឡូម៉ែត្រ។ ពហុកោណទំហំធំមួយនៅប៉ែកឦសានប្រទេសស៊ុយអែត (ID: EU-2227059) ត្រូវបានបំបែកជា ១៧២ ផ្នែកតូចៗ ដែលមានកំណត់ត្រាខ្សែបន្ទាត់សរុបចំនួន ៥៤៧,៣៤៤។
ការបង្រួមទំហំឯកសារចែករំលែក (Download size optimization) ការផ្លាស់ប្តូរវិធីសាស្ត្រចែករំលែកទិន្នន័យពីឯកសារ shapefiles តាមប្រភេទគម្របដី ទៅជាការផ្តល់ឯកសារតាមទម្រង់ក្រឡា (Tiles) ដែលមានរចនាសម្ព័ន្ធតូប៉ូឡូស៊ី អាចផ្តល់អត្ថប្រយោជន៍ដល់អ្នកប្រើប្រាស់ចុងក្រោយក្នុងការទាញយក។ របាយការណ៍បានរកឃើញថា ការប្រើប្រាស់ក្រឡាដែលមានតូប៉ូឡូស៊ី នឹងជួយកាត់បន្ថយទំហំទាញយកទិន្នន័យបានប្រមាណ ៤០ ភាគរយ។

៣. អនុសាសន៍ (Recommendations)

របាយការណ៍នេះផ្តល់នូវអនុសាសន៍សំខាន់ៗដើម្បីកែលម្អការគ្រប់គ្រង ការធ្វើបច្ចុប្បន្នភាព និងការចែករំលែកសំណុំទិន្នន័យភូមិសាស្ត្រខ្នាតធំឱ្យមានប្រសិទ្ធភាព និងងាយស្រួលក្នុងការប្រើប្រាស់។

គោលដៅ (Target) សកម្មភាព (Action) អាទិភាព (Priority)
ស្ថាប័នគ្រប់គ្រងទិន្នន័យភូមិសាស្ត្រ (Geospatial Data Agencies) គួរកំណត់ទំហំ និងភាពស្មុគស្មាញអតិបរមានៃពហុកោណ (Polygons) ដោយធ្វើការបំបែកពហុកោណធំៗតាមព្រំដែននៃរចនាសម្ព័ន្ធធម្មជាតិជាក់ស្តែង (ឧទាហរណ៍៖ កាត់ផ្តាច់តាមខ្សែទឹកទន្លេ ឬស្ទឹង)។ ខ្ពស់ (High)
អ្នកអភិវឌ្ឍន៍មូលដ្ឋានទិន្នន័យ (Database Developers) ត្រូវបង្កើតប្រព័ន្ធលេខសម្គាល់តែមួយគត់ (Unique identifiers) សម្រាប់កំណត់ត្រានីមួយៗ ដើម្បីងាយស្រួលតាមដានការផ្លាស់ប្តូរ និងធ្វើបច្ចុប្បន្នភាពតែទិន្នន័យដែលប្រែប្រួល ជៀសវាងការជំនួសឯកសារទាំងស្រុង។ ខ្ពស់ (High)
អ្នកផ្តល់សេវាទិន្នន័យសាធារណៈ (Public Data Providers) ក្រៅពីការផ្តល់ឯកសារតាមប្រភេទចំណាត់ថ្នាក់ដី គួរផ្តល់ជម្រើសឱ្យអ្នកប្រើប្រាស់អាចទាញយកទិន្នន័យជាទម្រង់ក្រឡា (Tiles ទំហំប្រមាណ ២៥០x២៥០ គ.ម) ដែលរួមបញ្ចូលរចនាសម្ព័ន្ធតូប៉ូឡូស៊ី ដើម្បីកាត់បន្ថយទំហំឯកសារទាញយក។ មធ្យម (Medium)

៤. បរិបទកម្ពុជា (Cambodia Context)

របាយការណ៍នេះមានសារៈសំខាន់ខ្លាំងសម្រាប់ប្រទេសកម្ពុជា ដែលបច្ចុប្បន្នកំពុងអភិវឌ្ឍប្រព័ន្ធហេដ្ឋារចនាសម្ព័ន្ធទិន្នន័យភូមិសាស្ត្រថ្នាក់ជាតិ (NSDI) ក៏ដូចជាការធ្វើផែនទីគម្របព្រៃឈើ និងការប្រើប្រាស់ដីធ្លីថ្នាក់ជាតិ ដែលមានទិន្នន័យទំហំធំ។

ផលប៉ះពាល់មូលដ្ឋាន (Local Implications)៖

  • បរិស្ថាន និងព្រៃឈើ (Environment and Forestry): ក្រសួងបរិស្ថាន អាចអនុវត្តបច្ចេកទេសបំបែកទិន្នន័យ (Tiling) និងតូប៉ូឡូស៊ី សម្រាប់គ្រប់គ្រងទិន្នន័យតំបន់ការពារធម្មជាតិធំៗ (ដូចជា ដែនជម្រកសត្វព្រៃព្រៃឡង់) ដើម្បីជៀសវាងបញ្ហាគាំងប្រព័ន្ធកុំព្យូទ័រនៅពេលធ្វើការវិភាគ GIS។
  • រៀបចំដែនដី និងនគរូបនីយកម្ម (Land Management and Urban Planning): ក្រសួងរៀបចំដែនដី អាចប្រើប្រាស់ប្រព័ន្ធមូលដ្ឋានទិន្នន័យភូមិសាស្ត្រ (ដូចជា PostGIS/Oracle) ដើម្បីរក្សាទុកព្រំប្រទល់ក្បាលដីរាប់លាននៅទូទាំងប្រទេស ដែលអាចកាត់បន្ថយទំហំផ្ទុកទិន្នន័យស្ទួន និងបង្កើនល្បឿនសេវាកម្មផែនទីអនឡាញ (Web Map Services)។

ការផ្លាស់ប្តូរពីការប្រើប្រាស់ឯកសារ Shapefiles រាយប៉ាយ មកប្រើប្រាស់ប្រព័ន្ធមូលដ្ឋានទិន្នន័យភូមិសាស្ត្ររួមដែលមានលក្ខណៈតូប៉ូឡូស៊ី នឹងជួយស្ថាប័នរដ្ឋាភិបាលកម្ពុជាសន្សំសំចៃថវិកាលើការផ្ទុកទិន្នន័យ និងបង្កើនប្រសិទ្ធភាពចែករំលែកទិន្នន័យ។

៥. ផែនការអនុវត្ត (Implementation Roadmap)

ដើម្បីអនុវត្តតាមអនុសាសន៍នៃរបាយការណ៍នេះ គួរអនុវត្តតាមជំហានខាងក្រោម៖

  1. ការវាយតម្លៃហេដ្ឋារចនាសម្ព័ន្ធទិន្នន័យភូមិសាស្ត្រ (Geospatial Infrastructure Assessment): វាយតម្លៃសមត្ថភាពម៉ាស៊ីនមេ និងកម្មវិធីមូលដ្ឋានទិន្នន័យ (ឧ. PostgreSQL/PostGIS ឬ Oracle Spatial) នៅតាមក្រសួងពាក់ព័ន្ធ ដើម្បីកំណត់សមត្ថភាពក្នុងការផ្ទុកទិន្នន័យអវកាសកម្រិតប្រទេស។
  2. ការកែច្នៃទិន្នន័យទៅជាទម្រង់តូប៉ូឡូស៊ី (Converting Data to Topological Format): ធ្វើចំណាកស្រុក (Migrate) ទិន្នន័យគម្របដី និងក្បាលដីពីទម្រង់ Shapefile ទៅកាន់ម៉ូដែលតូប៉ូឡូស៊ីក្នុងមូលដ្ឋានទិន្នន័យ ដើម្បីលុបបំបាត់ការផ្ទុកព្រំដែនត្រួតស៊ីគ្នាទ្វេដង និងធានាភាពត្រឹមត្រូវនៃព្រំប្រទល់។
  3. ការបង្កើតប្រព័ន្ធក្រឡាចត្រង្គសម្រាប់ទិន្នន័យធំៗ (Establishing Tiling System for Large Data): អនុវត្តការបំបែកទិន្នន័យស្មុគស្មាញទៅជាក្រឡាខ្នាតស្តង់ដារ (ឧ. ១០០x១០០ គ.ម) ឬតាមព្រំដែនខេត្ត ដើម្បីសម្រួលដល់ប្រតិបត្តិការកុំព្យូទ័រ និងការទាញយករបស់សាធារណជន។
  4. ការរៀបចំយន្តការធ្វើបច្ចុប្បន្នភាពទិន្នន័យតាមផ្នែក (Incremental Data Update Mechanism): បង្កើតប្រព័ន្ធកំណត់លេខសម្គាល់ (Unique ID) សម្រាប់ទិន្នន័យនីមួយៗ និងរៀបចំយន្តការអនុញ្ញាតឱ្យមានការធ្វើបច្ចុប្បន្នភាពតែលើកំណត់ត្រាដែលប្រែប្រួល ដោយមិនចាំបាច់ជំនួសសំណុំទិន្នន័យជាតិទាំងមូលសារជាថ្មី។

៦. វាក្យសព្ទបច្ចេកទេស (Technical Glossary)

ពាក្យបច្ចេកទេស ការពន្យល់ជាខេមរភាសា (Khmer Explanation) និយមន័យសាមញ្ញ (Simple Definition)
Topological storage ជាវិធីសាស្ត្ររក្សាទុកទិន្នន័យភូមិសាស្ត្រដែលកត់ត្រាពីទំនាក់ទំនងរវាងវត្ថុផ្សេងៗក្នុងលំហ (ដូចជាព្រំប្រទល់ជាប់គ្នា)។ វាមិនរក្សាទុកខ្សែបន្ទាត់នៃព្រំដែនជាន់គ្នាចំនួនពីរដងនោះទេ តែវាប្រើប្រាស់ខ្សែបន្ទាត់រួមមួយសម្រាប់ផ្ទៃដែលជាប់គ្នា ដែលជួយកាត់បន្ថយទំហំទិន្នន័យ និងជៀសវាងភាពមិនច្បាស់លាស់នៃព្រំដែនក្នុងទិន្នន័យជាតិ។ ដូចជាការសាងសង់របងរួមមួយសម្រាប់ផ្ទះពីរដែលនៅជាប់គ្នា ជាជាងសាងសង់របងពីរជាន់គ្នា។
Shapefile ជាទម្រង់ឯកសារទិន្នន័យវ៉ិចទ័រ (Vector data) ស្តង់ដារសម្រាប់ប្រព័ន្ធ GIS ដែលរក្សាទុកទីតាំង រូបរាង និងលក្ខណៈសម្បត្តិនៃភូមិសាស្ត្រ។ ទោះយ៉ាងណា វាជួបប្រឈមក្នុងការរក្សាទុកទិន្នន័យព្រំដែនត្រួតស៊ីគ្នា (ផ្ទុកទិន្នន័យព្រំដែនទ្វេដង) ដែលធ្វើឱ្យឯកសារមានទំហំធំ និងពិបាកដំណើរការសម្រាប់ទិន្នន័យកម្រិតប្រទេស។ ដូចជាផ្ទាំងរូបភាពកាត់ត (Jigsaw puzzle) ដែលដុំនីមួយៗមានគែមរៀងៗខ្លួន ហើយពេលយកមកផ្គុំចូលគ្នា គែមរបស់វាត្រួតស៊ីគ្នា។
Oracle Spatial ជាមុខងារបន្ថែមរបស់ប្រព័ន្ធគ្រប់គ្រងមូលដ្ឋានទិន្នន័យ Oracle ដែលអនុញ្ញាតឱ្យគេអាចរក្សាទុក វិភាគ និងដំណើរការទិន្នន័យភូមិសាស្ត្រ (Geometry/Geography) ទំហំធំនៅក្នុងប្រព័ន្ធកុំព្យូទ័រមជ្ឈមណ្ឌលរបស់ស្ថាប័ន ជួយសម្រួលដល់ការគ្រប់គ្រងទិន្នន័យដីធ្លីថ្នាក់ជាតិមានភាពរលូន។ ដូចជាទូដែកឆ្លាតវៃខ្នាតធំរបស់រដ្ឋាភិបាល ដែលអាចរៀបចំ រក្សាទុក និងស្វែងរកផែនទីរាប់លានសន្លឹកបានយ៉ាងឆាប់រហ័ស។
Tiling system ជាបច្ចេកទេសបំបែកទិន្នន័យផែនទីដែលមានទំហំធំ និងស្មុគស្មាញខ្លាំង ទៅជាបំណែកក្រឡាតូចៗ (ឧទាហរណ៍ ក្រឡាទំហំ ២៥០x២៥០ គីឡូម៉ែត្រ) ដើម្បីឱ្យប្រព័ន្ធកុំព្យូទ័រងាយស្រួលដំណើរការ ធ្វើបច្ចុប្បន្នភាព និងងាយស្រួលដល់ការទាញយកពីសំណាក់អ្នកប្រើប្រាស់ដោយមិនធ្វើឱ្យគាំងម៉ាស៊ីន។ ដូចជាការកាត់នំប៉័ងដ៏ធំមួយជាបន្ទះតូចៗ ដើម្បីងាយស្រួលចាប់កាន់ ទទួលទាន និងចែកចាយ។
Polygon ជារូបរាងបិទជិតនៅលើផែនទីឌីជីថល (បង្កើតដោយខ្សែបន្ទាត់ភ្ជាប់គ្នាពីចំណុចមួយទៅចំណុចមួយ) ដែលប្រើសម្រាប់តំណាងឱ្យផ្ទៃដីជាក់លាក់ណាមួយ ដូចជាផ្ទៃបឹង តំបន់គម្របព្រៃឈើ ឬព្រំប្រទល់ខេត្ត។ ពហុកោណធំពេក ឬស្មុគស្មាញពេក អាចធ្វើឱ្យប្រព័ន្ធទិន្នន័យដំណើរការយឺត។ ដូចជាការយកប៊ិចគូសបន្ទាត់វង់ជុំវិញកន្លែងណាមួយលើក្រដាសដើម្បីកំណត់ចំណាំថាវាជាតំបន់តែមួយ។
ArcINFO coverage ជាទម្រង់ទិន្នន័យផែនទីជំនាន់មុនរបស់កម្មវិធី GIS ដែលមានរចនាសម្ព័ន្ធតូប៉ូឡូស៊ីភ្ជាប់ជាមួយស្រាប់ ដើម្បីរក្សាទុកចំណុច ខ្សែបន្ទាត់ និងពហុកោណ ដោយធានាបាននូវទំនាក់ទំនងលំហច្បាស់លាស់រវាងធាតុផែនទី ជួយសម្រួលដល់ការវិភាគផែនទីស្មុគស្មាញ។ ដូចជាប្លង់មេសំណង់ដែលគូសវាសដោយស្ថាបត្យករ ដែលកំណត់យ៉ាងច្បាស់ជញ្ជាំងបន្ទប់នីមួយៗនៅទីណា ដោយគ្មានការគូសជាន់គ្នាឡើយ។
LAEA projection system Lambert Azimuthal Equal Area (LAEA) ជាប្រព័ន្ធចំណោលផែនទី (Map Projection) មួយប្រភេទដែលរក្សាទំហំផ្ទៃដីនៅលើផែនទីឱ្យមានភាពត្រឹមត្រូវដូចផ្ទៃជាក់ស្តែង ប៉ុន្តែវាអាចធ្វើឱ្យទ្រង់ទ្រាយរូបរាងប្រទេសខូចបន្តិចបន្តួច។ វាស័ក្តិសមបំផុតសម្រាប់ការងារវាស់វែងទំហំដីនៃតំបន់ធំៗ ដូចជាទ្វីបអឺរ៉ុបទាំងមូល។ ដូចជាការយកសំបកក្រូចពោធិ៍សាត់ដែលមូល មកសង្កត់ឱ្យសំប៉ែតលើតុ ដោយការព្យាយាមរក្សាទំហំសំបកក្រូចឱ្យនៅដដែល ទោះបីវាត្រូវបែករាងខុសពីដើមក៏ដោយ។
