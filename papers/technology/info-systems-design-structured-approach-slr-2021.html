វិធីសាស្ត្រ (The Methodology)៖ ការស្រាវជ្រាវនេះត្រូវបានធ្វើឡើងដោយប្រើវិធីសាស្ត្រពិនិត្យអក្សរសិល្ប៍ជាប្រព័ន្ធ (Systematic Literature Review - SLR) លើអត្ថបទដែលបានបោះពុម្ពពីឆ្នាំ 2010 ដល់ 2021។

  • ការប្រមូលទិន្នន័យពីមូលដ្ឋានទិន្នន័យ Garuda (Garuda Database Collection)
  • ការប្រើប្រាស់កម្មវិធី NVivo 12 Plus សម្រាប់ការវិភាគទិន្នន័យ (Data Analysis using NVivo 12 Plus)
  • ការធ្វើចំណាត់ថ្នាក់តាមវេទិកា និងប្រភេទស្ថាប័ន (Classification by Platform and Institution Type)

លទ្ធផលសំខាន់ៗ (The Verdict)៖

  • ការប្រើប្រាស់ដ្យាក្រាមលំហូរទិន្នន័យ (Data Flow Diagrams - DFD) ក្នុងការរចនាប្រព័ន្ធព័ត៌មានមានការកើនឡើងគួរឱ្យកត់សម្គាល់នៅក្នុងឆ្នាំ 2018 និង 2019។
  • ការរចនាប្រព័ន្ធមូលដ្ឋានទិន្នន័យដោយប្រើដ្យាក្រាមទំនាក់ទំនងអង្គភាព (Entity Relationship Diagrams - ERD) មានការកើនឡើងខ្ពស់នៅក្នុងឆ្នាំ 2019។
  • វិសាលភាពដែលត្រូវបានសិក្សាច្រើនជាងគេបំផុតគឺ ការអនុវត្តប្រព័ន្ធនៅក្នុងស្ថាប័នរកប្រាក់ចំណេញ ស្ថាប័នអប់រំ និងទីភ្នាក់ងាររដ្ឋាភិបាល។

២. ការវិភាគលើប្រសិទ្ធភាព និងការចំណាយ (Performance & Constraints)

វិធីសាស្ត្រ (Method) គុណសម្បត្តិ (Pros) គុណវិបត្តិ (Cons) លទ្ធផលគន្លឹះ (Key Result)
Data Flow Diagram (DFD)
ដ្យាក្រាមលំហូរទិន្នន័យ		 ងាយស្រួលក្នុងការយល់ពីលំហូរនៃប្រព័ន្ធតាមរយៈកម្រិត (levels) ផ្សេងៗគ្នា និងជួយដោះស្រាយបញ្ហាប្រព័ន្ធបានយ៉ាងមានលំដាប់លំដោយ។ មានភាពស្មុគស្មាញនិងពិបាកមើល នៅពេលមានតួអង្គ (actors) និងលំហូរទិន្នន័យច្រើននៅក្នុងប្រព័ន្ធធំៗ។ ការប្រើប្រាស់មានការកើនឡើងខ្ពស់នៅក្នុងឆ្នាំ 2018 និង 2019 ជាពិសេសលើប្រព័ន្ធទូរស័ព្ទ និងកុំព្យូទ័រលើតុ។
Entity Relationship Diagram (ERD)
ដ្យាក្រាមទំនាក់ទំនងអង្គភាព		 ផ្តល់ការយល់ដឹងច្បាស់លាស់អំពីអង្គភាពទិន្នន័យ គុណលក្ខណៈ និងទំនាក់ទំនងរវាងទិន្នន័យក្នុងប្រព័ន្ធមូលដ្ឋានទិន្នន័យ។ ពន្យល់ពីទិន្នន័យក្នុងទម្រង់អរូបី (abstract) ខ្លាំង និងផ្តោតសំខាន់តែលើទិន្នន័យជាជាងលំហូរដំណើរការទូទៅនៃប្រព័ន្ធ។ មានប្រជាប្រិយភាពខ្ពស់ និងមានការកើនឡើងខ្លាំងនៅក្នុងឆ្នាំ 2019 សម្រាប់ការរចនាមូលដ្ឋានទិន្នន័យលើគ្រប់វេទិកាទាំងអស់ (Web, Mobile, Desktop)។

ការចំណាយលើធនធាន (Resource Cost)៖ ដោយសារឯកសារនេះគឺជាការសិក្សាស្រាវជ្រាវបែបពិនិត្យអក្សរសិល្ប៍ជាប្រព័ន្ធ (SLR) ធនធានចម្បងដែលត្រូវការគឺកម្មវិធីគ្រប់គ្រងទិន្នន័យស្រាវជ្រាវ និងប្រភពទិន្នន័យឌីជីថល។

  • Software: ទាមទារកម្មវិធី NVivo 12 Plus សម្រាប់ការវិភាគទិន្នន័យគុណវិស័យ (Coding និង Project Mapping) និង Mendeley សម្រាប់ការគ្រប់គ្រងឯកសារយោង។
  • Dataset: ត្រូវការប្រភពទិន្នន័យអត្ថបទស្រាវជ្រាវពីវិបផតថល Garuda (garuda.ristekbrin.go.id) ចន្លោះឆ្នាំ 2010 ដល់ 2021។
  • Expertise: ទាមទារចំណេះដឹងលើវិធីសាស្ត្រ Systematic Literature Review (SLR) និងការធ្វើកូដនីយកម្មទិន្នន័យ (Open, Selective, Axial coding)។

៣. ការពិនិត្យសម្រាប់បរិបទកម្ពុជា/អាស៊ីអាគ្នេយ៍

ភាពលំអៀងនៃទិន្នន័យ (Data Bias)៖

ការសិក្សានេះត្រូវបានធ្វើឡើងដោយផ្អែកលើអត្ថបទស្រាវជ្រាវដែលបានបោះពុម្ពនៅក្នុងប្រទេសឥណ្ឌូនេស៊ី (Garuda database) ពីឆ្នាំ 2010-2021 តែប៉ុណ្ណោះ។ ទិន្នន័យនេះឆ្លុះបញ្ចាំងពីបរិបទនៃការអភិវឌ្ឍន៍ប្រព័ន្ធព័ត៌មាននៅក្នុងប្រទេសឥណ្ឌូនេស៊ីដែលជានិន្នាការក្នុងតំបន់។ សម្រាប់ប្រទេសកម្ពុជា វាមានសារៈសំខាន់ក្នុងការយល់ដឹងពីនិន្នាការនេះ ដោយសារប្រទេសទាំងពីរមានបរិបទកំពុងអភិវឌ្ឍន៍ស្រដៀងគ្នា និងកំពុងជំរុញការធ្វើឌីជីថលនីយកម្មដូចគ្នា។

លទ្ធភាពនៃការអនុវត្ត (Applicability)៖

វិធីសាស្ត្ររចនាដែលមានរចនាសម្ព័ន្ធ (Structured Approach) ដោយប្រើ DFD និង ERD នេះមានអត្ថប្រយោជន៍យ៉ាងខ្លាំងសម្រាប់ការអភិវឌ្ឍន៍ប្រព័ន្ធព័ត៌មាននៅកម្ពុជា។

  • សហគ្រាសធុនតូច និងមធ្យម (SMEs): អាជីវកម្មនៅកម្ពុជាអាចប្រើប្រាស់គំរូ DFD និង ERD ដើម្បីរៀបចំប្រព័ន្ធគ្រប់គ្រងការលក់ និងស្តុករបស់ពួកគេឱ្យមានស្តង់ដារមុននឹងឈានទៅប្រើប្រាស់ប្រព័ន្ធ ERP ធំៗ។
  • គំនិតផ្តួចផ្តើមរដ្ឋាភិបាលអេឡិចត្រូនិក (E-Government): ស្ថាប័នរដ្ឋអាចអនុវត្តការរចនានេះដើម្បីធ្វើឌីជីថលនីយកម្មសេវាសាធារណៈ ដូចជាការគ្រប់គ្រងទិន្នន័យប្រជាពលរដ្ឋ ឬការគ្រប់គ្រងរដ្ឋបាលថ្នាក់ឃុំ-សង្កាត់ ឱ្យមានលំហូរច្បាស់លាស់។
  • ស្ថាប័នអប់រំ និងសាកលវិទ្យាល័យ (Higher Education): សាកលវិទ្យាល័យនៅកម្ពុជាអាចបន្តប្រើប្រាស់វិធីសាស្ត្រនេះជាមូលដ្ឋានគ្រឹះក្នុងការបង្រៀនមុខវិជ្ជា Software Engineering ដល់និស្សិត ដើម្បីធានាថាពួកគេយល់ច្បាស់ពីតក្កវិជ្ជានៃប្រព័ន្ធ។

៤. ផែនការសកម្មភាពសម្រាប់និស្សិត (Actionable Roadmap)

ដើម្បីអនុវត្តតាមការសិក្សានេះ និស្សិតគួរអនុវត្តតាមជំហានខាងក្រោម៖

  1. សិក្សាមូលដ្ឋានគ្រឹះនៃការវិភាគ និងរចនាប្រព័ន្ធ: ចាប់ផ្តើមរៀនពីរបៀបគូស Data Flow Diagram (DFD) សម្រាប់ដំណើរការអាជីវកម្ម និង Entity Relationship Diagram (ERD) សម្រាប់មូលដ្ឋានទិន្នន័យ ដោយប្រើប្រាស់កម្មវិធីឥតគិតថ្លៃដូចជា Draw.io ឬ Lucidchart។
  2. កំណត់តម្រូវការប្រព័ន្ធជាក់ស្តែង (Requirements Elicitation): ជ្រើសរើសស្ថាប័នណាមួយ (ឧទាហរណ៍៖ សាលារៀន ឬគ្លីនិក) ដើម្បីធ្វើការប្រមូលតម្រូវការមុខងារ (Functional Requirements) និងប្រើប្រាស់ DFD ដើម្បីមើលពីលំហូរទិន្នន័យរបស់ស្ថាប័ននោះ។
  3. អនុវត្តការស្រាវជ្រាវតាមបែប SLR សម្រាប់គម្រោងបញ្ចប់ឆ្នាំ: រៀនប្រើប្រាស់កម្មវិធី Mendeley ឬ Zotero ដើម្បីប្រមូល គ្រប់គ្រង និងធ្វើសេចក្តីយោងអត្ថបទស្រាវជ្រាវ មុននឹងចាប់ផ្តើមសរសេរនិក្ខេបបទស្តីពីការអភិវឌ្ឍន៍ប្រព័ន្ធ។
  4. រៀនប្រើប្រាស់កម្មវិធីវិភាគទិន្នន័យគុណវិស័យ: សិក្សាពីរបៀបប្រើប្រាស់កម្មវិធី NVivo ដើម្បីធ្វើចំណាត់ថ្នាក់ទិន្នន័យ (Coding) និងបង្កើត Project Map សម្រាប់វិភាគទំនាក់ទំនងរវាងអថេរផ្សេងៗក្នុងការស្រាវជ្រាវប្រព័ន្ធព័ត៌មាន។
  5. អនុវត្តការសរសេរកូដ និងគ្រប់គ្រងមូលដ្ឋានទិន្នន័យ: យកដ្យាក្រាម ERD ដែលបានគូសរួចទៅបង្កើតជាតារាងមូលដ្ឋានទិន្នន័យពិតប្រាកដ ដោយប្រើប្រាស់ប្រព័ន្ធគ្រប់គ្រងទិន្នន័យដូចជា MySQL, PostgreSQL ឬ SQL Server។

៥. វាក្យសព្ទបច្ចេកទេស (Technical Glossary)

ពាក្យបច្ចេកទេស (English) ការពន្យល់ជាខេមរភាសា (Khmer Explanation) និយមន័យសាមញ្ញ (Simple Definition)
Systematic Literature Review វិធីសាស្ត្រស្រាវជ្រាវដែលប្រមូល វាយតម្លៃ និងសំយោគភស្តុតាងពីការសិក្សាស្រាវជ្រាវមុនៗទាំងអស់ដែលពាក់ព័ន្ធនឹងសំណួរស្រាវជ្រាវជាក់លាក់ណាមួយ ដោយប្រើយន្តការច្បាស់លាស់ និងមានប្រព័ន្ធ។ ដូចជាការប្រមូលសៀវភៅទាំងអស់ក្នុងបណ្ណាល័យដែលនិយាយពីប្រធានបទមួយ មកអានសង្ខេប និងទាញសេចក្តីសន្និដ្ឋានតែមួយដែលគួរឱ្យទុកចិត្តបំផុត។
Data Flow Diagram ឧបករណ៍សម្រាប់គូសបង្ហាញពីលំហូរនៃទិន្នន័យចូលនិងចេញពីប្រព័ន្ធព័ត៌មាន ដោយបង្ហាញពីប្រភពទិន្នន័យ ដំណើរការ និងកន្លែងផ្ទុកទិន្នន័យ។ ដូចជាផែនទីបង្ហាញផ្លូវទឹក ដែលប្រាប់យើងថាទឹកហូរពីណា ឆ្លងកាត់ម៉ាស៊ីនចម្រោះអ្វីខ្លះ និងទៅស្តុកទុកនៅអាងណា។
Entity Relationship Diagram គំរូដ្យាក្រាមដែលប្រើសម្រាប់រចនាមូលដ្ឋានទិន្នន័យ ដោយបង្ហាញពីអង្គភាព (Entities) គុណលក្ខណៈ (Attributes) និងទំនាក់ទំនង (Relationships) រវាងទិន្នន័យ។ ដូចជាតារាងមែកធាងគ្រួសារ ដែលបង្ហាញថាអ្នកណាជាកូនអ្នកណា និងមានទំនាក់ទំនងសាច់ញាតិគ្នាយ៉ាងដូចម្តេច។
Software Development Life Cycle វដ្តជីវិតនៃការអភិវឌ្ឍន៍កម្មវិធីកុំព្យូទ័រ ដែលរួមមានដំណាក់កាលជាបន្តបន្ទាប់ដូចជា ការរៀបចំផែនការ ការវិភាគ ការរចនា ការសរសេរកូដ ការធ្វើតេស្ត និងការថែទាំ។ ដូចជាដំណើរការសាងសង់ផ្ទះ ដែលត្រូវចាប់ផ្តើមពីការគូសប្លង់ ចាក់គ្រឹះ សង់ជញ្ជាំង ប្រក់ដំបូល និងចុងក្រោយគឺការលាបថ្នាំ និងថែទាំ។
Waterfall វិធីសាស្ត្រមួយនៃ SDLC ដែលដំណើរការអភិវឌ្ឍន៍ត្រូវធ្វើឡើងជាជំហានៗតាមលំដាប់លំដោយពីលើចុះក្រោម ហើយមិនអាចត្រឡប់ទៅជំហានមុនបានទេលុះត្រាតែបញ្ចប់គម្រោង។ ដូចជាទឹកធ្លាក់ពីលើភ្នំ ដែលហូរតាមកាំជណ្តើរម្តងមួយថ្នាក់ៗ ហើយមិនអាចហូរត្រឡប់ទៅលើវិញបានទេ។
Database Management System ប្រព័ន្ធកម្មវិធីកុំព្យូទ័រដែលត្រូវបានប្រើដើម្បីបង្កើត គ្រប់គ្រង និងទាញយកទិន្នន័យពីមូលដ្ឋានទិន្នន័យ (Database) ឱ្យមានសុវត្ថិភាពនិងប្រសិទ្ធភាព។ ដូចជាបណ្ណារក្សដែលជួយរៀបចំសៀវភៅតាមទូ ស្វែងរកសៀវភៅឱ្យអ្នកអាន និងការពារមិនឱ្យសៀវភៅបាត់បង់។
Axial coding នីតិវិធីក្នុងការវិភាគទិន្នន័យគុណវិស័យ (Qualitative Data) ដែលទិន្នន័យត្រូវបានផ្តុំបញ្ចូលគ្នាវិញបន្ទាប់ពីបានបំបែកជាចំណែកតូចៗ ដើម្បីស្វែងរកទំនាក់ទំនងរវាងប្រភេទឬអថេរនៃទិន្នន័យ។ ដូចជាការយកបំណែករូបភាពផ្គុំ (Jigsaw puzzle) ដែលបានចាក់ពង្រាយ មកផ្គុំបញ្ជូលគ្នាវិញជារូបភាពធំមួយដែលមានអត្ថន័យ។
