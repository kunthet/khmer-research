វិស័យសិក្សា៖ Telecommunications / Internet of Things

១. សេចក្តីសង្ខេបប្រតិបត្តិ (Executive Summary)

បញ្ហា (The Problem)៖ បណ្តាញ LoRaWAN ធម្មតាប្រើប្រាស់ការជ្រើសរើសប៉ុស្តិ៍ដោយចៃដន្យ និងមានការរឹតបន្តឹងលើវដ្តការងារ (duty-cycle) ដែលបណ្តាលឱ្យមានការពន្យារពេលយ៉ាងខ្លាំងក្នុងការបញ្ជូនទិន្នន័យធំៗ (ដូចជារូបភាព) នៅក្នុងប្រព័ន្ធ IoT ។

វិធីសាស្ត្រ (The Methodology)៖ ការស្រាវជ្រាវនេះបានស្នើឡើងនូវវិធីសាស្ត្រកំណត់កាលវិភាគតំណភ្ជាប់ដោយផ្អែកលើក្រុមអាទិភាព ដោយប្រើប្រាស់ច្រកទ្វារបណ្តាញ (Gateway) ដើម្បីណែនាំប៉ុស្តិ៍បញ្ជូនទិន្នន័យ។

  • ការធ្វើតេស្តលទ្ធភាពបញ្ជូនរូបភាពជាក់ស្តែង (Image Transmission Feasibility Test) តាមរយៈម៉ូឌុល LoRa
  • ការបង្កើតក្បួនដោះស្រាយការកំណត់កាលវិភាគផ្អែកលើក្រុមអាទិភាព (Priority-Group based Link Scheduling Algorithm)
  • ការក្លែងធ្វើបណ្តាញ (Network Simulation) ដោយប្រើប្រាស់កម្មវិធី LoRaSIM ដែលត្រូវបានកែលម្អ

លទ្ធផលសំខាន់ៗ (The Verdict)៖

  • ប្រព័ន្ធ LoRaPS ដែលបានស្នើឡើងអាចបង្កើនអត្រាទទួលបានទិន្នន័យដោយជោគជ័យខ្ពស់ជាងមុន។
  • កាត់បន្ថយពេលវេលាបញ្ជូនទិន្នន័យធំៗបានលឿនជាងបណ្តាញ LoRaWAN ធម្មតាជាង 10 ដង។
  • ធានាបាននូវការអនុលោមតាមដែនកំណត់វដ្តការងារ (Duty-cycle limits) ខណៈពេលរក្សាបាននូវប្រសិទ្ធភាពសម្រាប់ទាំងទិន្នន័យធំនិងតូច។

២. ការវិភាគលើប្រសិទ្ធភាព និងដែនកំណត់ (Performance & Constraints)

វិធីសាស្ត្រ (Method) គុណសម្បត្តិ (Pros) គុណវិបត្តិ (Cons) លទ្ធផលគន្លឹះ (Key Result)
Priority-Group based Link Scheduling (LoRaPS)
ការកំណត់កាលវិភាគតំណភ្ជាប់ដោយផ្អែកលើក្រុមអាទិភាព (LoRaPS)		 ផ្តល់អាទិភាពដល់ទិន្នន័យធំ (រូបភាព) ដែលជួយកាត់បន្ថយពេលវេលាបញ្ជូនទិន្នន័យបានយ៉ាងច្រើន និងកាត់បន្ថយការបុកគ្នា (Collision) នៃទិន្នន័យ។ វាគោរពតាមដែនកំណត់ Duty-Cycle យ៉ាងតឹងរ៉ឹង។ តម្រូវឱ្យមានការប្រើប្រាស់បណ្តាញបញ្ជូនត្រលប់ (Downlink) ដើម្បីបញ្ជូនព័ត៌មានកាលវិភាគដែលអាចស៊ីពេលវេលា Duty-cycle សរុបរបស់ Gateway បន្តិចបន្តួច។ កាត់បន្ថយពេលវេលាបញ្ជូនទិន្នន័យធំជាងមុនជាង ១០ដង និងបង្កើនអត្រាទទួលបានទិន្នន័យដោយជោគជ័យខ្ពស់ (Frame Reception Ratio)។
Typical LoRaWAN (Variable Frame Length)
LoRaWAN ធម្មតា (ប្រើប្រាស់ទំហំ Frame ប្រែប្រួល)		 ងាយស្រួលក្នុងការអនុវត្តដោយមិនត្រូវការផ្លាស់ប្តូរ MAC layer និងមានអត្រាទទួលបានទិន្នន័យល្អប្រសើរជាងការប្រើ Frame ទំហំធំថេរ។ ប្រើប្រាស់ពេលវេលាយូរខ្លាំងក្នុងការបញ្ជូនទិន្នន័យធំៗ (ការពន្យារពេលខ្ពស់) ដោយសារការជ្រើសរើសប៉ុស្តិ៍ដោយចៃដន្យ (Random channel access) ដែលធ្វើឱ្យប៉ះទង្គិចជាមួយទិន្នន័យតូចៗ។ អត្រាបាត់បង់ទិន្នន័យមានកម្រិតទាបសមរម្យ ប៉ុន្តែមានការពន្យារពេលយូរខ្លាំងក្នុងការបញ្ជូនរូបភាពដែលមិនស័ក្តិសមសម្រាប់តម្រូវការបន្ទាន់។
Typical LoRaWAN (Large Frame Length)
LoRaWAN ធម្មតា (ប្រើប្រាស់ទំហំ Frame ធំថេរ)		 កាត់បន្ថយចំនួនកញ្ចប់ទិន្នន័យ (Frames) ដែលត្រូវបញ្ជូន ដែលធ្វើឱ្យការបញ្ជូនទិន្នន័យធំលឿនជាងការប្រើ Frame ប្រែប្រួលបន្តិចក្នុងករណីមានឧបករណ៍តិច។ មានអត្រាបាត់បង់ទិន្នន័យ និងការបុកគ្នា (Collision) ខ្ពស់បំផុតនៅពេលចំនួនឧបករណ៍ (Nodes) ក្នុងបណ្តាញកើនឡើង។ អត្រាទទួលបានទិន្នន័យជោគជ័យធ្លាក់ចុះយ៉ាងខ្លាំងត្រឹមតែ ២០% ប៉ុណ្ណោះ នៅពេលមានឧបករណ៍លើសពី ៥០ បញ្ជូនទិន្នន័យព្រមគ្នា។

ការចំណាយលើធនធាន (Resource Cost)៖ ការស្រាវជ្រាវនេះទាមទារទាំងផ្នែករឹង (Hardware) សម្រាប់ការធ្វើតេស្តជាក់ស្តែងកម្រិតតូច និងកម្មវិធីក្លែងធ្វើ (Simulator) សម្រាប់ការវាយតម្លៃទ្រង់ទ្រាយធំរហូតដល់ ១០០០ ឧបករណ៍។

  • Hardware: បន្ទះឧបករណ៍ LoRa Mini Development Board (ប្រើឈីប SX1276/SX1278), កុំព្យូទ័រ (PC) សម្រាប់ទទួលទិន្នន័យ, និងឧបករណ៍សេនស័រកាមេរ៉ាខ្នាតតូច។
  • Software: កម្មវិធី Arduino IDE សម្រាប់សរសេរកូដលើឧបករណ៍បញ្ជូន, ភាសា Python (បណ្ណាល័យ PySerial សម្រាប់ភ្ជាប់រូបភាព), និងកម្មវិធីក្លែងធ្វើបណ្តាញ LoRaSIM ដែលត្រូវបានកែសម្រួលដើម្បីគាំទ្រការកំណត់អាទិភាព។
  • Expertise: ចំណេះដឹងស៊ីជម្រៅលើប្រព័ន្ធបណ្តាញ LoRaWAN, ភាសា C/C++ និង Python, ព្រមទាំងការយល់ដឹងពី MAC layer protocols ការគណនាពេលវេលាបញ្ជូន (Time on Air) និងច្បាប់ប្រេកង់ Duty-Cycle។

៣. ការពិនិត្យសម្រាប់បរិបទកម្ពុជា/អាស៊ីអាគ្នេយ៍

ភាពលំអៀងនៃទិន្នន័យ (Data Bias)៖

ការធ្វើតេស្តក្លែងធ្វើត្រូវបានកំណត់យកស្តង់ដារប្រេកង់ AS923 ដែលប្រើប្រាស់នៅប្រទេសជប៉ុន និងប្រទេសមួយចំនួននៅអាស៊ីអាគ្នេយ៍ (សិង្ហបុរី ម៉ាឡេស៊ី ឥណ្ឌូនេស៊ី)។ ទិន្នន័យសាកល្បងគឺផ្អែកលើទំហំរូបភាពកសិដ្ឋានចិញ្ចឹមក្តាម និងទិន្នន័យសីតុណ្ហភាពទឹក។ នេះមានសារៈសំខាន់សម្រាប់កម្ពុជា ព្រោះកម្ពុជាក៏ស្ថិតក្នុងតំបន់ដែលអាចអនុវត្តស្តង់ដារប្រេកង់ AS923 សម្រាប់ការអភិវឌ្ឍន៍បច្ចេកវិទ្យា IoT ក្នុងវិស័យកសិកម្មប្រកបដោយភាពស៊ីសង្វាក់គ្នា។

លទ្ធភាពនៃការអនុវត្ត (Applicability)៖

វិធីសាស្ត្រនេះមានសក្តានុពលខ្ពស់ណាស់សម្រាប់ប្រទេសកម្ពុជា ជាពិសេសក្នុងការកសាងប្រព័ន្ធ IoT ឆ្លាតវៃតាមតំបន់ជនបទឬតំបន់ដាច់ស្រយាលដែលគ្មានសេវាអ៊ីនធឺណិតល្បឿនលឿន។

  • កសិកម្ម និងវារីវប្បកម្មឆ្លាតវៃ (តំបន់ឆ្នេរខេត្តកំពត/កែប): ស័ក្តិសមបំផុតសម្រាប់ការចិញ្ចឹមក្តាមសក ឬបង្គា ដោយអាចបញ្ជូនទិន្នន័យគុណភាពទឹកព្រមជាមួយរូបភាពពីកាមេរ៉ាជាប្រចាំដើម្បីតាមដានការលូតលាស់ ដោយចំណាយថាមពលអគ្គិសនីតិចបំផុត។
  • ការអភិរក្សព្រៃឈើ និងសត្វព្រៃ (ជួរភ្នំក្រវាញ ឬតំបន់ព្រៃឡង់): អាចប្រើប្រាស់កាមេរ៉ាសេនស័រចាប់ចលនា (Camera Traps) បំពាក់ប្រព័ន្ធ LoRa ដែលអាចរស់នៅជាមួយថ្មបានយូរឆ្នាំ ដើម្បីបញ្ជូនរូបភាពជាបន្ទាន់នៅពេលមានបទល្មើសព្រៃឈើ ឬសត្វព្រៃកាត់ កាត់បន្ថយការដើរប្រមូលទិន្នន័យដោយផ្ទាល់។
  • ប្រព័ន្ធធារាសាស្រ្តឆ្លាតវៃ (សហគមន៍កសិកម្មខេត្តបាត់ដំបង): អនុញ្ញាតឱ្យប្រមូលទិន្នន័យសំណើមដីជាបន្តបន្ទាប់ រួមផ្សំជាមួយការថតរូបភាពស្ថានភាពដំណាំ ដើម្បីកំណត់ការបើកប្រព័ន្ធស្រោចស្រពដោយស្វ័យប្រវត្តិទោះបីគ្មានសេវា 4G ចូលដល់ក៏ដោយ។

សរុបមក ក្បួនដោះស្រាយ LoRaPS នេះផ្តល់លទ្ធភាពឱ្យស្ថាប័នស្រាវជ្រាវកម្ពុជាអាចប្រើប្រាស់បណ្តាញ LoRa តម្លៃថោកដើម្បីបញ្ជូនទាំងទិន្នន័យសេនស័រតូចៗ និងរូបភាពសំខាន់ៗក្នុងពេលតែមួយបានយ៉ាងមានប្រសិទ្ធភាពនិងទាន់ពេលវេលា។

៤. ផែនការសកម្មភាពសម្រាប់និស្សិត (Actionable Roadmap)

ដើម្បីអនុវត្តតាមការសិក្សានេះ និស្សិតគួរអនុវត្តតាមជំហានខាងក្រោម៖

  1. សិក្សាមូលដ្ឋានគ្រឹះនៃឧបករណ៍និងរចនាសម្ព័ន្ធបណ្តាញ: និស្សិតត្រូវស្វែងយល់ពីការកំណត់រចនាសម្ព័ន្ធរបស់ LoRaWAN MAC Layer រួមមានគោលការណ៍ ALOHA របៀបគណនា Time on Air (ToA) សម្រាប់ Spreading Factor (SF) ផ្សេងៗគ្នា និងច្បាប់កំណត់ពេលវេលា Duty-Cycle នៃស្តង់ដារប្រេកង់ AS923។
  2. តម្លើងនិងសាកល្បងផ្នែករឹងកម្រិតមូលដ្ឋាន: ទិញបន្ទះសៀគ្វី LoRa Mini Development Board និងប្រើប្រាស់កម្មវិធី Arduino IDE ជាមួយបណ្ណាល័យ RH_RF95 ដើម្បីសរសេរកូដបញ្ជូនទិន្នន័យអក្សរ និងសាកល្បងបំបែករូបភាពខ្នាតតូច (ឧ. 128x128 pixels) ជាកញ្ចប់ Byte array បញ្ជូនពីឧបករណ៍មួយទៅឧបករណ៍មួយទៀត។
  3. អនុវត្តកម្មវិធីក្លែងធ្វើបណ្តាញ (Network Simulation): ទាញយកនិងសិក្សាពីកម្មវិធីក្លែងធ្វើ LoRaSIM ដែលប្រើប្រាស់ភាសា Python។ អនុវត្តកែប្រែកូដបន្ថែមមុខងារ Data Fragmentation សម្រាប់រូបភាពធំៗ និងបង្កើតឧបករណ៍សេនស័រប្រភេទតូចនិងធំឱ្យដំណើរការព្រមគ្នាក្នុង Simulator។
  4. អភិវឌ្ឍមុខងារកាលវិភាគអាទិភាព (Priority Scheduling): សរសេរក្បួនដោះស្រាយ (Algorithm) សម្រាប់ Gateway ដើម្បីប្រមូលទិន្នន័យ RSSI ត្រួតពិនិត្យភាពទំនេរនៃប៉ុស្តិ៍ប្រេកង់ និងបែងចែកអាទិភាព (Priority Group 00 ឬ 11) រួចបញ្ជូនទិន្នន័យ Channel Status Update ទៅកាន់ឧបករណ៍វិញតាមរយៈ Downlink។
  5. ធ្វើតេស្តនិងប្រមូលទិន្នន័យក្នុងបរិស្ថានជាក់ស្តែង: យកប្រព័ន្ធដែលបានរៀបចំរួចទៅធ្វើតេស្តផ្ទាល់នៅកសិដ្ឋាន ឬទីតាំងសាកល្បងក្នុងសាកលវិទ្យាល័យដោយដាក់ឧបករណ៍ឱ្យឆ្ងាយពីគ្នា។ ប្រើប្រាស់ PySerial ដើម្បីប្រមូលរូបភាពដែលទទួលបាន និងវាស់ស្ទង់អត្រាបាត់បង់ទិន្នន័យ (Packet Loss) ប្រៀបធៀបជាមួយឯកសារដើម។

៥. វាក្យសព្ទបច្ចេកទេស (Technical Glossary)

ពាក្យបច្ចេកទេស ការពន្យល់ជាខេមរភាសា (Khmer Explanation) និយមន័យសាមញ្ញ (Simple Definition)
Duty-Cycle វិធានការកំណត់ភាគរយនៃពេលវេលាអតិបរមាដែលឧបករណ៍មួយត្រូវបានអនុញ្ញាតឱ្យបញ្ជូនទិន្នន័យនៅលើប្រេកង់ណាមួយ ដើម្បីធានាថាមិនមានការប្រើប្រាស់ប្រេកង់ផ្តាច់មុខ។ បើវាប្រើប្រាស់ដល់កំណត់ (ឧ. ១០% ក្នុងមួយម៉ោង) ឧបករណ៍នោះត្រូវផ្អាកនិងរង់ចាំ (time-off) ទើបអាចបញ្ជូនបន្តបាន។ ដូចជាការកំណត់ម៉ោងនិយាយក្នុងអង្គប្រជុំ ដោយម្នាក់ៗមានសិទ្ធិនិយាយត្រឹមតែ ៥នាទី ដើម្បីទុកឱកាសឱ្យអ្នកដទៃបាននិយាយដែរ។
Spreading Factor (SF) ប៉ារ៉ាម៉ែត្រកំណត់ល្បឿននៃការបញ្ជូនសញ្ញាវិទ្យុ (Chirp) នៅក្នុងបណ្តាញ LoRa។ លេខ SF កាន់តែធំ (ឧទាហរណ៍ SF12) ការបញ្ជូនទិន្នន័យកាន់តែយឺត ប៉ុន្តែវាអាចបញ្ជូនបានកាន់តែឆ្ងាយ និងធន់នឹងការរំខានសេវា។ ដូចជាការនិយាយយឺតៗនិងច្បាស់ៗទៅកាន់មនុស្សដែលនៅឆ្ងាយ ដើម្បីឱ្យគេស្តាប់បាន ទោះបីជាត្រូវចំណាយពេលយូរជាងការនិយាយលឿនៗក៏ដោយ។
Time on Air (ToA) រយៈពេលជាក់ស្តែងដែលកញ្ចប់ទិន្នន័យមួយប្រើប្រាស់ដើម្បីធ្វើដំណើរតាមរលកអាកាសពីឧបករណ៍បញ្ជូនទៅកាន់ឧបករណ៍ទទួល។ វាប្រែប្រួលទៅតាមទំហំទិន្នន័យ និងកម្រិតនៃ Spreading Factor ដែលបានប្រើ។ ដូចជារយៈពេលដែលសំបុត្រមួយច្បាប់ចំណាយពេលធ្វើដំណើរតាមម៉ូតូឌុបពីអ្នកផ្ញើទៅដល់ដៃអ្នកទទួល។
Slotted ALOHA ពិធីការគ្រប់គ្រងការបញ្ជូនទិន្នន័យ ដែលបែងចែកពេលវេលាជាចន្លោះៗ (Slots) ស្មើៗគ្នា។ ឧបករណ៍អាចចាប់ផ្តើមបញ្ជូនទិន្នន័យបានតែនៅពេលផ្តើមនៃចន្លោះនីមួយៗប៉ុណ្ណោះ ដែលជួយកាត់បន្ថយការបុកគ្នានៃទិន្នន័យ បើធៀបនឹងការបញ្ជូនតាមចិត្ត។ ដូចជាការរៀបចំចំណតឡានដែលមានគូសបន្ទាត់ច្បាស់លាស់ ជួយឱ្យឡានចូលចតមានសណ្តាប់ធ្នាប់ កាត់បន្ថយការបុកគ្នា ជាជាងការចតអនាធិបតេយ្យ។
Capture Effect បាតុភូតមួយដែលកើតឡើងនៅពេលមានសញ្ញាពីរឆ្លងកាត់គ្នាក្នុងពេលតែមួយនៅលើប៉ុស្តិ៍ប្រេកង់តែមួយ ហើយឧបករណ៍ទទួល (Gateway) អាចចាប់យកតែសញ្ញាណាដែលមានថាមពលខ្លាំងជាងគេមកបកប្រែ ដោយផាត់ចោលសញ្ញាដែលខ្សោយជាង។ ដូចជាមនុស្សពីរនាក់ស្រែកនិយាយព្រមគ្នា អ្នកដែលស្រែកឮជាងនឹងត្រូវគេស្តាប់បាន ខណៈសំឡេងអ្នកខ្សោយត្រូវលិចបាត់កណ្តាលអាកាស។
Received Signal Strength Indicator (RSSI) សូចនាករវាស់កម្រិតថាមពលនៃសញ្ញាវិទ្យុដែលឧបករណ៍ម្ខាងទៀតទទួលបាន។ គេប្រើប្រាស់កម្រិតនេះដើម្បីវាយតម្លៃថាតើសញ្ញាខ្លាំងឬខ្សោយ ព្រមទាំងដើម្បីប៉ាន់ស្មានចម្ងាយរវាងឧបករណ៍សេនស័រ និង Gateway។ ដូចជាការស្តាប់កម្រិតសំឡេងវិទ្យុ បើសំឡេងកាន់តែឮច្បាស់ មានន័យថាស្ថានីយវិទ្យុនៅកាន់តែជិតយើង។
Orthogonality លក្ខណៈសម្បត្តិដែលអាចឱ្យសញ្ញាដែលមានកម្រិត SF ខុសៗគ្នា បញ្ជូនលើប៉ុស្តិ៍ប្រេកង់តែមួយ និងក្នុងពេលតែមួយបាន ដោយមិនមានការរំខានឬបុកគ្នា ព្រោះឧបករណ៍ទទួលអាចបំបែកសញ្ញាទាំងនោះដាច់ពីគ្នាបាន។ ដូចជាមនុស្សពីរនាក់និយាយគ្នាក្នុងបន្ទប់តែមួយ ប៉ុន្តែម្នាក់និយាយភាសាខ្មែរ ម្នាក់ទៀតនិយាយអង់គ្លេស ដែលធ្វើឱ្យពួកគេមិនច្រឡំគ្នាស្តាប់។
Link Scheduling យន្តការរៀបចំកាលវិភាគបញ្ជូនទិន្នន័យ ដោយកំណត់ថាឧបករណ៍សេនស័រណាគួរប្រើប្រាស់ប៉ុស្តិ៍ប្រេកង់មួយណា និងនៅចន្លោះម៉ោងណា ដើម្បីជៀសវាងការស្ទះបណ្តាញ និងពន្លឿនការបញ្ជូនទិន្នន័យដែលមានអាទិភាពខ្ពស់។ ដូចជាប៉ូលីសចរាចរណ៍ដែលឈរនៅផ្លូវបំបែក ដើម្បីសម្រួលថាឡានណាគួរទៅមុន ឡានណាគួររង់ចាំ ដើម្បីកុំឱ្យស្ទះចរាចរណ៍។
