ចំណងជើងដើម៖ SIDERA - a Simulation Model for Time-Triggered Distributed Real-Time Systems

១. សេចក្តីសង្ខេបប្រតិបត្តិ (Executive Summary)

បញ្ហា (The Problem)៖ ឯកសារនេះដោះស្រាយបញ្ហានៃការធ្វើសមកាលកម្មនាឡិកា (Clock Synchronization) នៅក្នុងប្រព័ន្ធកុំព្យូទ័រចែកចាយពេលវេលាជាក់ស្តែងដែលទាមទារភាពសុក្រឹតខ្ពស់ ដោយមិនចាំបាច់ពឹងផ្អែកខ្លាំងលើឧបករណ៍វាស់ស្ទង់ (Oscillators) ដែលមានតម្លៃថ្លៃ។

វិធីសាស្ត្រ (The Methodology)៖ ការសិក្សានេះបានអភិវឌ្ឍនិងប្រើប្រាស់គំរូក្លែងធ្វើ SIDERA ដើម្បីវាយតម្លៃ និងប្រៀបធៀបក្បួនដោះស្រាយការធ្វើសមកាលកម្មនាឡិកាផ្សេងៗគ្នានៅក្នុងបណ្តាញចែកចាយ។

  • ការអភិវឌ្ឍគំរូក្លែងធ្វើ SIDERA (SIDERA Simulation Model)
  • ស្ថាបត្យកម្មដំណើរការដោយផ្អែកលើពេលវេលា (Time-Triggered Architecture - TTA)
  • ការធ្វើសមកាលកម្មនាឡិកាខាងក្នុង និងខាងក្រៅ (Internal and External Clock Synchronization)
  • ការក្លែងធ្វើកំហុសដើម្បីសាកល្បងស្ថិរភាពប្រព័ន្ធ (Failure Simulation Module)

លទ្ធផលសំខាន់ៗ (The Verdict)៖

  • ក្បួនដោះស្រាយថ្មីដែលរួមបញ្ចូលការកែតម្រូវស្ថានភាពនាឡិកា និងអត្រានាឡិកាកណ្តាល បានបង្កើនភាពសុក្រឹតនៃប្រព័ន្ធ Cluster តែមួយរហូតដល់ 500% ពោលគឺពី 20 មកត្រឹម 4 microticks ។
  • សម្រាប់ប្រព័ន្ធដែលមាន Cluster ច្រើន (Multi-cluster System) ក្បួនដោះស្រាយនេះបានកែលម្អភាពសុក្រឹតរហូតដល់ 400% គឺពី 22 មកត្រឹម 5 microticks ។
  • អភិក្រមនេះអាចរក្សាភាពត្រឹមត្រូវខ្ពស់ដោយកាត់បន្ថយតម្រូវការក្នុងការប្រើប្រាស់ឧបករណ៍ Oscillators គុណភាពខ្ពស់ ដែលជួយសន្សំសំចៃថ្លៃដើមសម្រាប់ការផលិតទ្រង់ទ្រាយធំដូចជាក្នុងវិស័យយានយន្ត។

២. ការវិភាគលើប្រសិទ្ធភាព និងដែនកំណត់ (Performance & Constraints)

វិធីសាស្ត្រ (Method) គុណសម្បត្តិ (Pros) គុណវិបត្តិ (Cons) លទ្ធផលគន្លឹះ (Key Result)
Fault-tolerant clock state correction (TTA standard)
ការកែតម្រូវស្ថានភាពនាឡិកាដែលធន់នឹងកំហុស (ស្តង់ដារ TTA)		 អាចរក្សាសមកាលកម្មនាឡិកាក្នុងប្រព័ន្ធបាន ទោះបីជាមានកំហុសផ្នែករឹងឬការបញ្ជូនទិន្នន័យមួយចំនួនក៏ដោយ។ ភាពសុក្រឹតនៃពេលវេលានៅមានកម្រិត និងទាមទារឧបករណ៍វាស់ស្ទង់អត្រាពេលវេលា (Oscillators) ដែលមានគុណភាពខ្ពស់ទើបដំណើរការល្អ។ សម្រេចបានភាពសុក្រឹតកម្រិត 14 ដល់ 20 microticks សម្រាប់ Single-cluster និង 22 microticks សម្រាប់ Multi-cluster។
Combined clock state and central clock rate correction
ការកែតម្រូវស្ថានភាពនាឡិកា និងអត្រានាឡិកាកណ្តាលរួមបញ្ចូលគ្នា (ក្បួនដោះស្រាយថ្មី)		 បង្កើនភាពសុក្រឹតនៃប្រព័ន្ធបានពី 300% ទៅ 500% និងកាត់បន្ថយតម្រូវការប្រើប្រាស់ឧបករណ៍ Oscillators ដែលមានតម្លៃថ្លៃនៅតាម Node នីមួយៗ។ ទាមទារការកំណត់រចនាសម្ព័ន្ធស្មុគស្មាញជាងមុនបន្តិច ដោយតម្រូវឲ្យមាន Node មួយធ្វើជា Rate Master Node ដើម្បីគ្រប់គ្រងអត្រាពេលវេលា។ ភាពសុក្រឹតត្រូវបានកែលម្អរហូតដល់កម្រិត 4 microticks សម្រាប់ Single-cluster និង 5 microticks សម្រាប់ Multi-cluster។

ការចំណាយលើធនធាន (Resource Cost)៖ ការក្លែងធ្វើតាមរយៈ SIDERA ត្រូវបានរចនាឡើងដើម្បីកាត់បន្ថយការចំណាយ ដោយមិនទាមទារផ្នែករឹង (Hardware) ពិសេសណាមួយឡើយ ហើយអាចដំណើរការលើកុំព្យូទ័រធម្មតាបាន។

  • Software Environment: កម្មវិធី SIDERA ដំណើរការលើប្រព័ន្ធប្រតិបត្តិការ Linux (Kernel 2.6) សរសេរដោយភាសា C++ និងប្រើប្រាស់ Qt សម្រាប់បង្កើតចំណុចប្រទាក់ក្រាហ្វិក (GUI)។
  • Hardware Requirements: កុំព្យូទ័រយួរដៃ ឬកុំព្យូទ័រលើតុធម្មតាមួយគ្រឿង (Single workstation) គឺគ្រប់គ្រាន់សម្រាប់ការក្លែងធ្វើប្រព័ន្ធខ្នាតធំដែលមាន Node ច្រើន។
  • Cost Savings (Practical Implementation): ក្បួនដោះស្រាយថ្មីនេះជួយកាត់បន្ថយថ្លៃដើមក្នុងការផលិត ដោយអនុញ្ញាតឱ្យប្រើប្រាស់ Oscillators គុណភាពមធ្យម (ថោកជាង) ជំនួសឱ្យគុណភាពខ្ពស់។

លទ្ធភាពនៃការអនុវត្ត (Applicability)៖

វិធីសាស្រ្តនេះមានសក្តានុពល និងអត្ថប្រយោជន៍ខ្ពស់សម្រាប់វិស័យវិស្វកម្មកុំព្យូទ័រ និងប្រព័ន្ធស្វ័យប្រវត្តិកម្មឧស្សាហកម្មនៅកម្ពុជា ជាពិសេសក្នុងការរចនាប្រព័ន្ធដែលមានតម្លៃទាបតែមានប្រសិទ្ធភាពខ្ពស់។

  • វិស័យដំឡើងយានយន្ត (Automotive Assembly): កម្ពុជាកំពុងមានរោងចក្រដំឡើងរថយន្តដូចជា Ford និង Hyundai។ ការយល់ដឹងពីក្បួននេះអាចជួយវិស្វករខ្មែរក្នុងការអភិវឌ្ឍ ឬថែទាំប្រព័ន្ធ Drive-by-wire ក្នុងរថយន្ត ដោយកាត់បន្ថយការចំណាយលើគ្រឿងបន្លាស់។
  • ស្វ័យប្រវត្តិកម្មឧស្សាហកម្ម (Industrial Automation): ការធ្វើសមកាលកម្មនាឡិកាមានសារៈសំខាន់សម្រាប់ការបញ្ជាគ្រឿងចក្ររោងចក្រ (Robotic Arms/Sensors) ក្នុងពេលជាក់ស្តែង ដើម្បីធានាដំណើរការខ្សែសង្វាក់ផលិតកម្មរលូន និងគ្មានកំហុសលំអៀង។
  • ស្ថាប័នស្រាវជ្រាវ និងសាកលវិទ្យាល័យ (ឧ. ITC, RUPP): និស្សិតផ្នែកវិស្វកម្មទូរគមនាគមន៍ និងវិទ្យាសាស្ត្រកុំព្យូទ័រអាចប្រើប្រាស់គំរូក្លែងធ្វើនេះ ដើម្បីសិក្សាស៊ីជម្រៅពី Distributed Systems និង Fault Tolerance ដោយមិនចាំបាច់ទិញឧបករណ៍ថ្លៃៗ។

៤. ផែនការសកម្មភាពសម្រាប់និស្សិត (Actionable Roadmap)

ដើម្បីអនុវត្តតាមការសិក្សានេះ និស្សិតគួរអនុវត្តតាមជំហានខាងក្រោម៖

  1. សិក្សាពីមូលដ្ឋានគ្រឹះនៃពេលវេលាជាក់ស្តែង (Real-Time Systems): និស្សិតត្រូវស្វែងយល់ពីគោលគំនិតសំខាន់ៗនៃ Time-Triggered Architecture (TTA) និងភាពខុសគ្នារវាងការធ្វើសមកាលកម្មនាឡិកាខាងក្នុង (Internal) និងខាងក្រៅ (External)។
  2. រៀបចំបរិស្ថានសូហ្វវែរ (Software Environment Setup): ដំឡើងប្រព័ន្ធប្រតិបត្តិការ Linux និងរៀបចំកម្មវិធីសរសេរកូដ C++ ព្រមទាំង Qt Framework ដើម្បីត្រៀមលក្ខណៈរចនាកម្មវិធីក្លែងធ្វើ (Simulator) ឬសាកល្បងដំណើរការ SIDERA demo version។
  3. ក្លែងធ្វើបណ្តាញសាមញ្ញ (Single-Cluster Simulation): ចាប់ផ្តើមបង្កើតគំរូក្លែងធ្វើដែលមាន Node ចំនួនតូច (ឧទាហរណ៍ ៦ ទៅ ៨ Nodes) រួចអនុវត្តក្បួន Fault-tolerant clock state correction ដើម្បីសង្កេតមើល និងវាស់ស្ទង់ភាពសុក្រឹតនៃការបញ្ជូនទិន្នន័យ។
  4. អនុវត្តក្បួនដោះស្រាយរួមបញ្ចូលគ្នា (Combined Algorithm): សាកល្បងបន្ថែម Rate Master Node ទៅក្នុងប្រព័ន្ធក្លែងធ្វើរបស់អ្នក រួចប្រៀបធៀបលទ្ធផលភាពសុក្រឹត (Precision) ថាតើវាអាចកាត់បន្ថយពី ២០ មកត្រឹម ៤ microticks ដូចការសិក្សាបានបង្ហាញឬទេ។
  5. ភ្ជាប់ទៅនឹងគម្រោងជាក់ស្តែង (IoT Hardware Integration): អនុវត្តក្បួនដោះស្រាយនេះលើ Hardware ជាក់ស្តែងដោយប្រើប្រាស់ Microcontrollers (ឧទាហរណ៍ ESP32 ឬ STM32) ដើម្បីរចនាប្រព័ន្ធទិន្នន័យ Sensor Networks ដែលទាមទារសមកាលកម្មពេលវេលាខ្ពស់ដោយចំណាយតិច។

៥. វាក្យសព្ទបច្ចេកទេស (Technical Glossary)

ពាក្យបច្ចេកទេស ការពន្យល់ជាខេមរភាសា (Khmer Explanation) និយមន័យសាមញ្ញ (Simple Definition)
Time-Triggered Architecture (TTA) ជាស្ថាបត្យកម្មប្រព័ន្ធកុំព្យូទ័រដែលដំណើរការ និងការបញ្ជូនទិន្នន័យទាំងអស់ត្រូវបានកំណត់ដោយពេលវេលាជាក់លាក់ជាមុន (Pre-scheduled) ជាជាងពឹងផ្អែកលើព្រឹត្តិការណ៍ (Event-triggered) ដើម្បីធានាបាននូវភាពជឿជាក់និងការឆ្លើយតបទាន់ពេលវេលា។ ដូចជារថភ្លើងដែលចេញដំណើរតាមកាលវិភាគម៉ោងជាក់លាក់ ដោយមិនរង់ចាំទាល់តែមានអ្នកដំណើរពេញនោះទេ។
Time Division Multiple Access (TDMA) ជាយន្តការគ្រប់គ្រងការប្រើប្រាស់បណ្តាញទំនាក់ទំនងរួម ដោយបែងចែកពេលវេលាជាចន្លោះតូចៗ (Slots) ហើយផ្តល់សិទ្ធិឱ្យឧបករណ៍នីមួយៗបញ្ជូនទិន្នន័យតែក្នុងចន្លោះពេលរបស់វាប៉ុណ្ណោះ ដើម្បីការពារការបញ្ជូនទិន្នន័យជាន់គ្នា (Collision-free)។ ដូចជាការបែងចែកម៉ោងឱ្យសិស្សម្នាក់ៗឡើងនិយាយមុខថ្នាក់រៀនម្តងម្នាក់ៗ ដើម្បីកុំឱ្យនិយាយដណ្តើមគ្នា។
Microticks ជាឯកតារង្វាស់ពេលវេលាដ៏តូចបំផុតនៅក្នុងប្រព័ន្ធ ដែលបានមកពីចង្វាក់លោតនៃឧបករណ៍វាស់ស្ទង់ (Oscillator) របស់ឧបករណ៍ (Node) នីមួយៗផ្ទាល់។ ដោយសារឧបករណ៍មានគុណភាពខុសគ្នា Microticks នៃឧបករណ៍នីមួយៗអាចដើរលឿន ឬយឺតជាងគ្នាបន្តិចបន្តួច។ ដូចជាសូរសំឡេង "តក់ៗ" នៃទ្រនិចវិនាទីរបស់នាឡិកាដៃរៀងៗខ្លួន ដែលអាចដើរលឿនឬយឺតជាងគ្នាបន្តិចបន្តួច។
Macroticks ជាឯកតារង្វាស់ពេលវេលារួម (Global Time) ដែលឧបករណ៍ទាំងអស់ក្នុងបណ្តាញយល់ព្រមប្រើប្រាស់ទូទៅ។ វាត្រូវបានបង្កើតឡើងដោយការប្រមូលផ្តុំ Microticks ជាច្រើនបញ្ចូលគ្នា ហើយត្រូវបានកែតម្រូវជាប្រចាំតាមរយៈក្បួនដោះស្រាយ ដើម្បីឱ្យប្រព័ន្ធទាំងមូលមានពេលវេលាស្របគ្នា។ ដូចជាម៉ោងស្តង់ដារជាតិដែលមនុស្សគ្រប់គ្នាត្រូវសារ៉េនាឡិកាដៃរបស់ខ្លួនឱ្យត្រូវតាម ដើម្បីងាយស្រួលធ្វើការងាររួមគ្នា។
Fault-Tolerant Average (FTA) algorithm ជាក្បួនដោះស្រាយគណិតវិទ្យាសម្រាប់ធ្វើសមកាលកម្មនាឡិកា ដោយប្រមូលទិន្នន័យពេលវេលាពីឧបករណ៍ផ្សេងៗ រួចកាត់ចោលតម្លៃពេលវេលាដែលលឿនដាច់ និងយឺតដាច់បំផុត ហើយយកតែតម្លៃមធ្យមនៃទិន្នន័យដែលនៅសល់ ដើម្បីចៀសវាងការគណនាខុសដោយសារឧបករណ៍ណាមួយខូច។ ដូចជាការគណនាពិន្ទុមធ្យមរបស់អ្នកប្រកួតកីឡា ដោយគណៈកម្មការកាត់ចោលពិន្ទុខ្ពស់ដាច់ និងទាបដាច់ ដើម្បីឱ្យពិតប្រាកដនិងយុត្តិធម៌។
Gateway Node ជាឧបករណ៍កុំព្យូទ័រដែលតភ្ជាប់បណ្តាញកុំព្យូទ័រ (Cluster) ពីរផ្សេងគ្នាចូលគ្នា និងដើរតួជាអ្នកបញ្ជូនព័ត៌មានពេលវេលាពីបណ្តាញមួយទៅបណ្តាញមួយទៀត ដើម្បីធានាថាយន្តការដំណើរការឆ្លងបណ្តាញមានពេលវេលាស៊ីចង្វាក់គ្នា។ ដូចជាអ្នកបកប្រែភាសាដែលឈរនៅកណ្តាលរវាងក្រុមមនុស្សពីរប្រទេស ដើម្បីឱ្យពួកគេអាចប្រាស្រ័យទាក់ទងនិងធ្វើការងារស្រុះគ្នាបាន។
Rate Master Node ជាឧបករណ៍កុំព្យូទ័រគោលនៅក្នុងប្រព័ន្ធ ដែលនាឡិការបស់វាត្រូវបានគេចាត់ទុកជាស្តង់ដារយោង ទាំងសម្រាប់ស្ថានភាពពេលវេលា (Clock state) និងល្បឿននៃពេលវេលា (Clock rate) សម្រាប់ឱ្យឧបករណ៍ផ្សេងទៀតទាំងអស់ក្នុងបណ្តាញកែតម្រូវតាមវា។ ដូចជាមេក្រុមភ្លេងដែលកំណត់ចង្វាក់ភ្លេងឱ្យសមាជិកផ្សេងទៀតលេងតាមខ្លួន ដើម្បីឱ្យចេញជាបទភ្លេងតែមួយ។
Clique Avoidance ជាយន្តការតក្កវិជ្ជាក្នុងប្រព័ន្ធចែកចាយ ដែលការពារមិនឱ្យបណ្តាញកុំព្យូទ័រមួយបែកបាក់ទៅជាក្រុមតូចៗ (Cliques) ដែលមិនអាចទាក់ទងគ្នាបាន ដោយវាអនឡាញទាមទារឱ្យឧបករណ៍ណាដែលដំណើរការមិនស្របតាមសំឡេងភាគច្រើន ត្រូវតែផ្តាច់ខ្លួនឯងចេញពីប្រព័ន្ធដើម្បីការពារកុំឱ្យមានភាពវឹកវរ។ ដូចជាច្បាប់បោះឆ្នោតតាមសម្លេងភាគច្រើន បើអ្នកណាមិនដើរតាមគោលការណ៍រួមភាគច្រើនទេ ត្រូវដកខ្លួនចេញដើម្បីកុំឱ្យរំខានដល់ក្រុមទាំងមូល។
