១. សេចក្តីសង្ខេបប្រតិបត្តិ (Executive Summary)

បញ្ហា (The Problem)៖ ការស្វែងរកឯកសារពាក់ព័ន្ធពីប្រភពទិន្នន័យចម្រុះសម្រាប់សំណួរជាក់លាក់ (ដូចជាការពិនិត្យប៉ាតង់ និងការតាមដានសុវត្ថិភាពឧបករណ៍ពេទ្យ) ជួបការលំបាកយ៉ាងខ្លាំង ដោយសារតែការប្រើប្រាស់អុនតូឡូស៊ី (Ontology) ប្រពៃណីតម្រូវឱ្យមានការធ្វើលិបិក្រមឯកសារឡើងវិញជានិច្ចនៅពេលដែលអុនតូឡូស៊ីមានការផ្លាស់ប្តូរ។

វិធីសាស្ត្រ (The Methodology)៖ អ្នកស្រាវជ្រាវបានបង្កើតវិធីសាស្ត្រថ្មីមួយដោយប្រើប្រាស់ Search Ontology (SO) គួបផ្សំជាមួយ OntoQueryBuilder (OQB) ដើម្បីបំប្លែងច្បាប់អុនតូឡូស៊ីទៅជាសំណួរស្វែងរកនៅពេលប្រតិបត្តិការ (Search time) ដោយមិនប៉ះពាល់ដល់លិបិក្រមដើម។

  • ការអភិវឌ្ឍ Search Ontology (SO) ដោយផ្អែកលើភាសា Web Ontology Language (OWL) និង General Formal Ontology (GFO)
  • ការបង្កើតកម្មវិធី OntoQueryBuilder (OQB) ដើម្បីបំប្លែងទិន្នន័យអុនតូឡូស៊ីទៅជាសំណួរស្វែងរក Lucene (Lucene Queries) ដោយស្វ័យប្រវត្តិ
  • ការអនុវត្តជាក់ស្តែងក្នុងគម្រោង OntoVigilance សម្រាប់ការតាមដានសុវត្ថិភាពឧបករណ៍ពេទ្យផ្នែកអង់ដូស្កុប (Post-market Surveillance)

លទ្ធផលសំខាន់ៗ (The Verdict)៖

  • ប្រព័ន្ធនេះអនុញ្ញាតឱ្យអ្នកជំនាញអាចបង្កើតសំណួរស្វែងរកដ៏មានប្រសិទ្ធភាព និងស្មុគស្មាញដោយមិនចាំបាច់ដឹងពីវាក្យសម្ព័ន្ធសំណួរ (Query syntax) នោះទេ។
  • ការផ្លាស់ប្តូរ និងការពង្រីក Search Ontology មិនតម្រូវឱ្យមានការធ្វើលិបិក្រម (Re-indexing) និងការវិភាគឡើងវិញសម្រាប់បណ្តុំឯកសារទាំងមូលនោះទេ ដែលជួយសន្សំសំចៃពេលវេលា និងធនធាន។
  • ការធ្វើតេស្តលើគំរូដំបូងនៃ OntoQueryBuilder (OQB) បានបង្ហាញថាវាអាចបង្កើតសំណួរ Lucene យ៉ាងត្រឹមត្រូវ និងគាំទ្រដល់ប្រព័ន្ធស្វែងរកដូចជា Solr និង Elasticsearch សម្រាប់ការទាញយកព័ត៌មានពិតប្រាកដ។

២. ការវិភាគលើប្រសិទ្ធភាព និងការចំណាយ (Performance & Constraints)

វិធីសាស្ត្រ (Method) គុណសម្បត្តិ (Pros) គុណវិបត្តិ (Cons) លទ្ធផលគន្លឹះ (Key Result)
Proposed Approach: Search Ontology + OntoQueryBuilder
អភិក្រមស្នើឡើង៖ Search Ontology (SO) រួមជាមួយ OntoQueryBuilder (OQB)		 មិនតម្រូវឱ្យធ្វើលិបិក្រមឯកសារ (Re-indexing) ឡើងវិញរាល់ពេលមានការផ្លាស់ប្តូរអុនតូឡូស៊ី ដែលជួយសន្សំសំចៃពេលវេលា។ អនុញ្ញាតឱ្យអ្នកជំនាញបង្កើតសំណួរស្វែងរកស្មុគស្មាញដោយស្វ័យប្រវត្តិ។ មានភាពបត់បែនតិចតួចក្នុងការទាញយកព័ត៌មានស៊ីជម្រៅនៅពេលធ្វើលិបិក្រម (Index time) បើធៀបនឹងវិធីសាស្ត្រប្រពៃណី។ គំរូសាកល្បងនៃប្រព័ន្ធ OQB បានបង្ហាញពីភាពជោគជ័យក្នុងការបង្កើតសំណួរស្វែងរក Lucene Queries យ៉ាងត្រឹមត្រូវសម្រាប់ប្រព័ន្ធស្វែងរក។
Traditional Ontology-based Information Extraction (e.g., Sindice)
ការទាញយកព័ត៌មានតាមអុនតូឡូស៊ីបែបប្រពៃណី (ឧទាហរណ៍ Sindice)		 មានសមត្ថភាពខ្ពស់ក្នុងការទាញយកព័ត៌មាន អង្គគតិ (Entities) និងទំនាក់ទំនងស៊ីជម្រៅនៅពេលដំណើរការធ្វើលិបិក្រមឯកសារ។ ទាមទារឱ្យមានការធ្វើលិបិក្រមទិន្នន័យអត្ថបទទាំងអស់ឡើងវិញជានិច្ច នៅពេលដែលអុនតូឡូស៊ីមានការកែប្រែ ឬវិវត្ត។ បង្កើតបញ្ហាប្រឈមធំចំពោះការថែទាំប្រព័ន្ធដែលត្រូវធ្វើបច្ចុប្បន្នភាពអុនតូឡូស៊ីជាប្រចាំ។
GoPubMed System
ប្រព័ន្ធ GoPubMed		 មានប្រសិទ្ធភាពខ្ពស់ក្នុងការស្វែងរកឯកសារវេជ្ជសាស្ត្រពី PubMed ដោយប្រើប្រាស់អុនតូឡូស៊ី។ បង្ខំឱ្យអ្នកប្រើប្រាស់ផ្អែកលើចំណាត់ថ្នាក់ (Taxonomies) ដែលមានស្រាប់ក្នុងប្រព័ន្ធ ដែលកម្រិតភាពជាក់លាក់តាមតម្រូវការផ្ទាល់ខ្លួនរបស់អ្នកជំនាញ។ ខ្វះភាពបត់បែនសម្រាប់អ្នកប្រើប្រាស់ក្នុងការកំណត់ច្បាប់ស្វែងរក (Search rules) តាមការយល់ឃើញរបស់ខ្លួន។

ការចំណាយលើធនធាន (Resource Cost)៖ ឯកសារមិនបានបញ្ជាក់លម្អិតអំពីទំហំធនធានកុំព្យូទ័រនោះទេ ប៉ុន្តែវិធីសាស្ត្រនេះតម្រូវឱ្យមានប្រព័ន្ធម៉ាស៊ីនមេសម្រាប់ដំណើរការ Web Application និងម៉ាស៊ីនស្វែងរក (Search Engine) ដែលមានប្រសិទ្ធភាព។

  • Software Frameworks: ត្រូវការប្រព័ន្ធស្វែងរកព័ត៌មាន (Information Retrieval Systems) ដូចជា Apache Lucene, Solr ឬ Elasticsearch និងភាសា Web Ontology Language (OWL)។
  • Expertise: តម្រូវឱ្យមានអ្នកជំនាញក្នុងវិស័យ (Domain Experts ដូចជាវេជ្ជបណ្ឌិត ឬអ្នកត្រួតពិនិត្យប៉ាតង់) ដើម្បីកំណត់ច្បាប់ស្វែងរក និងពាក្យសទិសន័យក្នុងអុនតូឡូស៊ី។
  • Datasets: បណ្តុំឯកសារអត្ថបទពិតប្រាកដ (Full-text documents) ដូចជារបាយការណ៍វេជ្ជសាស្ត្រ ឬឯកសារប៉ាតង់សម្រាប់ធ្វើការស្វែងរក។

ភាពលំអៀងនៃទិន្នន័យ (Data Bias)៖

ការសិក្សានេះផ្តោតសំខាន់ទៅលើទិន្នន័យនៃការតាមដានសុវត្ថិភាពឧបករណ៍ពេទ្យ (ផ្នែកអង់ដូស្កុប) ក្នុងគម្រោង OntoVigilance នៅប្រទេសអាល្លឺម៉ង់។ សម្រាប់ប្រទេសកម្ពុជា ការយកប្រព័ន្ធនេះមកអនុវត្តតម្រូវឱ្យមានការកសាងអុនតូឡូស៊ី (Ontology) ជាភាសាខ្មែរ ឬស្របតាមបរិបទវេជ្ជសាស្ត្រ និងច្បាប់ក្នុងស្រុក ដែលបច្ចុប្បន្ននៅខ្វះខាតទិន្នន័យរចនាសម្ព័ន្ធបែបនេះនៅឡើយ។

  • ក្រសួងសុខាភិបាល (នាយកដ្ឋានឱសថ និងចំណីអាហារ): អាចប្រើប្រាស់ប្រព័ន្ធនេះដើម្បីបង្កើតយន្តការតាមដាន និងស្វែងរករបាយការណ៍ផលប៉ះពាល់នៃការប្រើប្រាស់ឧបករណ៍ពេទ្យ ឬឱសថ ដោយផ្អែកលើពាក្យបច្ចេកទេសនិងរោគសញ្ញា។
  • ក្រសួងពាណិជ្ជកម្ម និងបញ្ញាស្មារតី (Patent & Trademark Registry): ជួយសម្រួលដល់មន្ត្រីត្រួតពិនិត្យប៉ាតង់ក្នុងការទាញយកឯកសារស្រដៀងគ្នា ដើម្បីផ្ទៀងផ្ទាត់ភាពត្រឹមត្រូវមុននឹងចុះបញ្ជីប៉ាតង់ថ្មីៗ។
  • បណ្ណាល័យឌីជីថលនៃសាកលវិទ្យាល័យនានា: ជួយនិស្សិត និងអ្នកស្រាវជ្រាវកម្ពុជាអាចស្វែងរកអត្ថបទស្រាវជ្រាវ (Research Papers) តាមរយៈការតភ្ជាប់អត្ថន័យពាក្យ និងគំនិតដោយមិនចាំបាច់ប្រើវាក្យសម្ព័ន្ធស្វែងរកស្មុគស្មាញ។

ការបំបែកអុនតូឡូស៊ីចេញពីការធ្វើលិបិក្រមនេះ ផ្តល់ឱកាសឱ្យស្ថាប័នកម្ពុជាអាចកសាង និងកែសម្រួលប្រព័ន្ធស្វែងរករបស់ខ្លួនជាជំហានៗប្រកបដោយនិរន្តរភាព និងចំណាយទាប។

៤. ផែនការសកម្មភាពសម្រាប់និស្សិត (Actionable Roadmap)

ដើម្បីអនុវត្តតាមការសិក្សានេះ និស្សិតគួរអនុវត្តតាមជំហានខាងក្រោម៖

  1. ជំហានទី១៖ សិក្សាមូលដ្ឋានគ្រឹះនៃ Ontology: ចាប់ផ្តើមរៀនអំពីស្តង់ដារ Web Ontology Language (OWL) និងសាកល្បងប្រើប្រាស់កម្មវិធី Protégé ដើម្បីរចនានិងចងក្រងវាក្យសព្ទពាក់ព័ន្ធនឹងវិស័យណាមួយ (ឧទាហរណ៍ ច្បាប់ ឬវេជ្ជសាស្ត្រ)។
  2. ជំហានទី២៖ រៀបចំប្រព័ន្ធម៉ាស៊ីនស្វែងរក (Search Engine): សិក្សា និងធ្វើការដំឡើងប្រព័ន្ធ Information Retrieval Systems ដូចជា Apache Lucene, Solr ឬ Elasticsearch ដើម្បីធ្វើលិបិក្រម (Index) ឯកសារអត្ថបទសាកល្បង។
  3. ជំហានទី៣៖ កសាង Search Ontology តូចមួយ: រៀបចំបង្កើតអុនតូឡូស៊ីសម្រាប់ការស្វែងរក ដោយអនុវត្តតាមទម្រង់ General Formal Ontology (GFO) ដើម្បីកំណត់ទំនាក់ទំនងរវាងពាក្យ (Search Terms) និងគំនិត (Concepts) នៅក្នុងឯកសារ។
  4. ជំហានទី៤៖ អភិវឌ្ឍកម្មវិធីបំប្លែងសំណួរ (Query Builder): សរសេរកូដដោយប្រើប្រាស់ភាសា Java ឬ Python ដើម្បីបង្កើតកម្មវិធីស្រដៀងនឹង OntoQueryBuilder ដែលអាចអានទិន្នន័យពី OWL ហើយបំប្លែងវាទៅជាវាក្យសម្ព័ន្ធ Lucene Queries។
  5. ជំហានទី៥៖ ដាក់ឱ្យដំណើរការជាទម្រង់ Web Application: ភ្ជាប់ផ្នែកខាងក្រោយ (Backend) ជាមួយចំណុចប្រទាក់អ្នកប្រើប្រាស់ (Frontend) ដើម្បីឱ្យអ្នកជំនាញអាចធ្វើការស្វែងរកដោយគ្រាន់តែជ្រើសរើសប្រភេទឯកសារ ដោយឱ្យប្រព័ន្ធរៀបចំសំណួរស្វែងរកស្មុគស្មាញដោយស្វ័យប្រវត្តិ។

៥. វាក្យសព្ទបច្ចេកទេស (Technical Glossary)

ពាក្យបច្ចេកទេស (English) ការពន្យល់ជាខេមរភាសា (Khmer Explanation) និយមន័យសាមញ្ញ (Simple Definition)
Search Ontology ប្រព័ន្ធចំណាត់ថ្នាក់និងរចនាសម្ព័ន្ធពាក្យដែលប្រើដើម្បីកំណត់ទំនាក់ទំនងរវាងពាក្យគន្លឹះ និងគំនិត (Concepts) នៅក្នុងវិស័យណាមួយ ដើម្បីជួយម៉ាស៊ីនស្វែងរកយល់ពីអត្ថន័យនៃសំណួរ និងបង្កើតសំណួរស្វែងរកដោយស្វ័យប្រវត្តិ។ វាប្រៀបដូចជាវចនានុក្រមឆ្លាតវៃមួយដែលប្រាប់កុំព្យូទ័រថាពាក្យ "ឡាន" និង "រថយន្ត" គឺមានន័យដូចគ្នា ហើយសុទ្ធតែជាយានជំនិះ។
Semantic Search វិធីសាស្ត្រស្វែងរកទិន្នន័យដែលមិនគ្រាន់តែផ្អែកលើការផ្គូផ្គងអក្ខរាវិរុទ្ធ (Keyword matching) ប៉ុន្តែវាព្យាយាមយល់ពីបរិបទ អត្ថន័យពិតប្រាកដ និងទំនាក់ទំនងនៃសំណួររបស់អ្នកប្រើប្រាស់។ ដូចជាការសួរសំណួរទៅកាន់បណ្ណារក្សដែលដឹងពីអ្វីដែលអ្នកចង់បានពិតប្រាកដ ទោះបីជាអ្នកមិនបានប្រើពាក្យចំៗក៏ដោយ។
Web Ontology Language (OWL) ភាសាកម្មវិធីស្តង់ដារមួយដែលប្រើសម្រាប់សរសេរតំណាងចំណេះដឹង (Knowledge representation) លើអ៊ីនធឺណិត ដើម្បីឱ្យកុំព្យូទ័រអាចយល់ និងទាញយកទំនាក់ទំនងស្មុគស្មាញរវាងទិន្នន័យផ្សេងៗបាន។ ដូចជាសៀវភៅវេយ្យាករណ៍ និងវចនានុក្រមរួមបញ្ចូលគ្នា ដែលជួយឱ្យម៉ាស៊ីនកុំព្យូទ័រអាចអាន និងយល់ពីទំនាក់ទំនងនៃព័ត៌មាននៅលើអុីនធឺណិត។
Lucene queries ទម្រង់កូដឬវាក្យសម្ព័ន្ធសំណួរ (Query syntax) ជាក់លាក់ដែលប្រើប្រាស់ក្នុងប្រព័ន្ធស្វែងរកកូដចំហ Apache Lucene ដើម្បីបញ្ជាឱ្យម៉ាស៊ីនទាញយកទិន្នន័យចេញពីក្នុងលិបិក្រម (Index) ។ ដូចជារូបមន្តគណិតវិទ្យាដែលយើងសរសេរដើម្បីប្រាប់ម៉ាស៊ីនគិតលេខឱ្យធ្វើការគណនារកចម្លើយជាក់លាក់ណាមួយ។
Post-market surveillance (PMS) ដំណើរការនៃការតាមដាន ត្រួតពិនិត្យសុវត្ថិភាព និងប្រមូលទិន្នន័យពីផលប៉ះពាល់នៃការប្រើប្រាស់ឧបករណ៍ពេទ្យ ឬឱសថ បន្ទាប់ពីវាត្រូវបានអនុញ្ញាតឱ្យលក់នៅលើទីផ្សារជាសាធារណៈរួចរាល់។ ដូចជាការសាកសួរមតិអតិថិជន និងតាមដានបញ្ហាផ្សេងៗក្រោយពេលដែលទូរស័ព្ទម៉ូដែលថ្មីមួយត្រូវបានលក់ចេញ។
Information Extraction បច្ចេកវិទ្យាក្នុងការវិភាគអត្ថបទដោយស្វ័យប្រវត្តិ ដើម្បីទាញយកព័ត៌មានជាក់លាក់ ដូចជា ឈ្មោះ អង្គគតិ (Entities) និងទំនាក់ទំនងរវាងទិន្នន័យពីឯកសារដែលគ្មានរចនាសម្ព័ន្ធត្រឹមត្រូវ (Unstructured data)។ ដូចជាការប្រើប្រាស់ម៉ាស៊ីនស្កេនដ៏ឆ្លាតវៃមួយ ដើម្បីស្រង់យកតែឈ្មោះ និងលេខទូរស័ព្ទចេញពីក្នុងសៀវភៅប្រលោមលោកដ៏ក្រាស់មួយ។
Index time ដំណាក់កាលដែលប្រព័ន្ធម៉ាស៊ីនស្វែងរកធ្វើការអាន វិភាគ និងរៀបចំទិន្នន័យឯកសារទុកជាមុន ទៅក្នុងទម្រង់លិបិក្រម ដើម្បីត្រៀមលក្ខណៈសម្រាប់ការស្វែងរក។ ដូចជាពេលដែលបណ្ណារក្សកំពុងរៀបចំសៀវភៅថ្មីៗបញ្ចូលទៅក្នុងទូ និងសរសេរកាតចំណាត់ថ្នាក់ទុកជាមុន។
Boolean operators ពាក្យបញ្ជាតក្កវិទ្យា (ដូចជា AND, OR, NOT) ដែលត្រូវបានប្រើសម្រាប់ភ្ជាប់ ឬផ្តាច់ពាក្យគន្លឹះនៅក្នុងសំណួរស្វែងរក ដើម្បីពង្រីក ឬបង្រួមលទ្ធផលនៃការស្វែងរកឱ្យកាន់តែសុក្រឹត។ ដូចជាការប្រាប់អ្នកលក់ថា "ខ្ញុំចង់ទិញអាវពណ៌ក្រហម (AND) មានទំហំធំ ប៉ុន្តែមិនយក (NOT) អាវដៃខ្លីទេ"។
